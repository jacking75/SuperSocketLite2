SuperSocketLite 2 아키텍처와 실행 흐름

이 문서는 SuperSocketLite 라이브러리의 코드 구조, 서버 시작 과정, TCP/UDP 연결 처리, 수신 필터, 송신 큐, 세션 상태 전이, 확장 지점을 한 파일에서 읽을 수 있도록 정리한 문서입니다. 분석 기준은 현재 저장소의 SuperSocketLite, Tutorials, Docs 디렉터리입니다.

TargetFramework: net10.0 TCP: SocketAsyncEventArgs + Pipelines UDP: datagram listener + AppSession facade Protocol: IReceiveFilter<TRequestInfo>

1. 개요

SuperSocketLite 2는 애플리케이션 개발자가 네트워크 소켓을 직접 다루지 않고도 AppServer, AppSession, IReceiveFilter, IRequestInfo 중심으로 TCP/UDP 서버를 작성할 수 있게 하는 비동기 I/O 소켓 서버 라이브러리입니다. 현재 프로젝트는 .NET 10.0을 대상으로 하며, 모바일 게임 서버처럼 많은 연결과 작은 패킷이 자주 오가는 환경을 염두에 둔 구조입니다.

서버 개발자가 보는 표면

AppServer<TSession,TRequestInfo>를 상속하거나 기본 AppServer를 만들고, 이벤트를 등록하고, Setup()과 Start()를 호출합니다.

프레임워크 내부

SocketServerFactory가 TCP 또는 UDP 서버 구현을 만들고, 리스너와 세션을 생성하며, SAEA 풀과 송신 큐 풀을 관리합니다.

프로토콜 확장

바이트 스트림은 IReceiveFilter에서 애플리케이션 요청 객체로 변환됩니다. 고정 길이, 헤더+바디, 구분자 기반 프로토콜을 선택하거나 직접 구현합니다.

핵심 관점은 두 층으로 나누면 이해하기 쉽습니다. 애플리케이션 층은 세션과 요청을 다루고, 소켓 엔진 층은 리스닝, accept, receive, send, close를 책임집니다.

2. 전체 지도

아래 그림은 라이브러리의 주요 객체가 어떤 순서로 연결되는지 보여줍니다. 녹색 점은 클라이언트의 데이터가 서버 내부를 통과하는 방향을 나타냅니다.

3. 계층 구조

계층 주요 타입 책임 사용자가 주로 만지는 부분
Application API AppServer, AppServer<TSession,TRequestInfo>, AppSession 서버 설정, 세션 컨테이너, 이벤트, 요청 핸들러 호출, 세션별 송신 API 제공 커스텀 서버/세션 클래스, NewRequestReceived, NewSessionConnected
Protocol IReceiveFilter, FixedHeaderReceiveFilter, TerminatorReceiveFilter, IRequestInfo 수신 바이트를 요청 단위로 분할하고 도메인 요청 객체를 생성 패킷 구조별 ReceiveFilter, RequestInfo 모델
Socket Engine SocketServerFactory, AsyncSocketServer, UdpSocketServer, SocketSession TCP/UDP 서버 구현 선택, 연결 수락, 세션 생성, 송수신 상태 관리 대부분 직접 수정하지 않음. 성능 튜닝이나 버그 수정 시 읽는 영역
Listener TcpAsyncSocketListener, UdpSocketListener, SocketListenerBase 소켓 바인딩, Listen/Accept 또는 ReceiveFrom, 새 클라이언트 이벤트 발행 멀티 포트, 커스텀 accept 정책이 필요할 때
Common SmartPool, SendingQueue, ReuseLockBaseBuffer, ArraySegmentList 객체 풀링, 송신 큐, 버퍼 재사용, 프로토콜 파싱 보조 일반 사용자는 설정값으로 간접 조절

4. 서버 시작 흐름

서버 시작은 크게 Setup()과 Start()로 나뉩니다. Setup()은 설정과 내부 객체를 준비하고, Start()는 실제 리스너와 소켓 엔진을 실행합니다.

사용자는 server.Setup(config) 또는 server.Setup(port)를 호출합니다. 상태는 NotInitialized에서 Initializing으로 이동합니다.
루트 설정, 서버 설정, 로그 팩토리, 텍스트 인코딩, 스레드풀 설정이 준비됩니다.
ServerConfig.Port 또는 Listeners를 기반으로 ListenerInfo[]를 만듭니다.
사용자가 넘긴 IReceiveFilterFactory가 있으면 사용하고, 없으면 기본 팩토리를 생성합니다. 기본 AppServer는 명령행 필터를 씁니다.
SocketServerFactory.CreateSocketServer()가 SocketMode.Tcp면 AsyncSocketServer, SocketMode.Udp면 UdpSocketServer를 만듭니다.
Start()가 m_SocketServer.Start()를 호출하고 성공하면 서버 상태를 Running으로 바꿉니다.

핵심 호출 순서

AppServerBase.Setup()
  -> SetupBasic()
  -> SetupLogFactory()
  -> SetupListeners()
  -> SetupFinal()
  -> SetupSocketServer()

AppServerBase.Start()
  -> m_SocketServer.Start()
  -> OnStarted()

AppServer<TSession,TRequestInfo>.Start()는 기본 시작 후 세션 스냅샷, idle 세션 정리, collect-send 타이머를 추가로 시작합니다.

5. TCP 접속 흐름

TCP 모드에서는 TcpAsyncSocketListener가 AcceptAsync 루프를 돌고, 새 연결이 들어오면 AsyncSocketServer가 SAEA 풀에서 receive/send 객체를 꺼내 세션을 만듭니다.

세부 단계

Listener 시작
TcpAsyncSocketListener.Start()는 listen socket을 만들고 Bind(), Listen() 후 취소 가능한 AcceptLoopAsync()를 실행합니다.
Accept 완료
새 Socket을 받으면 OnNewClientAccepted(client, null) 이벤트를 올립니다.
세션 생성
AsyncSocketServer.ProcessNewClient()가 receive용 SocketAsyncEventArgsProxy와 send용 SocketAsyncEventArgs를 풀에서 가져와 AsyncSocketSession을 만듭니다.
AppSession 생성
TcpSocketServerBase.CreateSession()이 TCP 옵션을 적용한 뒤 AppServer.CreateAppSession()을 호출합니다.
등록 및 시작
AppServer.RegisterSession()이 성공하면 socketSession.Start()가 비동기로 실행됩니다.

6. 수신 파이프라인

현재 TCP 수신 경로는 SocketAsyncEventArgs와 System.IO.Pipelines를 결합합니다. 비동기 receive 완료 경로는 받은 바이트를 PipeWriter에 넣고, 별도 소비 루프가 PipeReader에서 읽어 AppSession.ProcessRequest()로 전달합니다.

생산자: AsyncSocketSession

  • Start()에서 StartReceive()와 ProcessPipeAsync()를 시작합니다.
  • StartReceive()는 _pipeWriter.GetMemory(Config.ReceiveBufferSize)로 버퍼를 받고 ReceiveAsync()를 게시합니다.
  • ProcessReceive()는 완료된 바이트 수만큼 Advance()하고 FlushAsync() 후 다시 receive를 걸어둡니다.

소비자: SocketSession.ProcessPipeAsync

  • PipeReader.ReadAsync()로 데이터를 읽습니다.
  • AppSession.ProcessRequest(ReadOnlySequence<byte>)가 기존 ReceiveFilter와 호환되도록 내부 carry buffer에 복사합니다.
  • 필터가 완전한 요청을 만들면 AppServer.ExecuteCommand()로 이벤트 핸들러가 호출됩니다.
이 구조는 비동기 소켓 완료 처리와 프로토콜 파싱을 분리합니다. 완료 콜백은 가능한 짧게 끝내고, 파싱과 핸들러 호출은 PipeReader 소비 루프에서 진행됩니다.

7. ReceiveFilter와 요청 처리

SuperSocketLite에서 프로토콜은 IReceiveFilter<TRequestInfo>로 구현됩니다. 필터는 스트림 또는 datagram에서 완전한 요청을 만들어 IRequestInfo 타입으로 반환합니다.

IReceiveFilter

Filter()는 받은 바이트 일부 또는 전체를 처리하고, 완전한 요청이 있으면 TRequestInfo를 반환합니다.

rest는 현재 버퍼에 아직 처리하지 않은 남은 바이트 수입니다.

FixedSizeReceiveFilter

고정 길이 패킷을 처리합니다. 패킷이 부족하면 m_ParsedLength와 OffsetDelta로 누적 상태를 유지합니다.

FixedHeaderReceiveFilter

먼저 고정 길이 헤더를 읽고, 헤더에서 바디 길이를 계산한 다음 바디까지 모아 요청 객체를 만듭니다.

요청 하나가 핸들러에 도달하는 과정

IAppSession.ProcessRequest(...)
  while true:
    requestInfo = FilterRequest(...)
      -> AppServer.OnRawDataReceived(...)
      -> m_ReceiveFilter.Filter(...)
      -> max request length check
      -> optional NextReceiveFilter switch

    if requestInfo != null:
      AppServer.ExecuteCommand(this, requestInfo)
        -> NewRequestReceived(session, requestInfo)

    if rest <= 0:
      return offsetDelta
    else:
      continue with remaining bytes
개념 의미 문서에서 기억할 점
requestInfo == null 아직 완전한 요청이 만들어지지 않음 부분 패킷 상태는 필터 내부 또는 AppSession carry buffer에 남습니다.
rest > 0 한 번의 receive 버퍼 안에 다음 요청의 일부 또는 전체가 남음 ProcessRequest 루프가 offset과 length를 조정해 이어서 처리합니다.
FilterState.Error 프로토콜 오류 상태 세션은 CloseReason.ProtocolError로 닫힙니다.
MaxRequestLength 한 요청의 최대 허용 길이 비정상적으로 큰 패킷을 차단하는 안전장치입니다.

8. 송신 파이프라인과 SendingQueue

송신은 AppSession.Send() 또는 TrySend()에서 시작되어 SocketSession.TrySend(), SendingQueue, 실제 socket send 순서로 진행됩니다. 핵심은 송신 중인 큐와 새 데이터를 받는 큐를 분리해 동시 송신을 제어하는 것입니다.

TrySend의 기본 흐름

AppSession.Send(data)
  -> SocketSession.TrySend(segment)
  -> current SendingQueue.Enqueue(...)
  -> StartSend(queue, trackID, initial: true)
  -> queue swap
  -> SendAsync(queue) or SendSync(queue)

큐 교체가 필요한 이유

어떤 스레드가 socket send를 진행하는 동안 다른 스레드가 다음 데이터를 계속 enqueue할 수 있어야 합니다.

StartSend()는 현재 큐를 send 대상으로 고정하고, 새 큐를 m_SendingQueue에 꽂아 다음 enqueue를 받게 합니다.

Collect Send

CollectSendIntervalMillSec > 0이면 세션은 ReuseLockBaseBuffer에 데이터를 모으고, AppServer<TSession,TRequestInfo>의 타이머가 세션별 collect buffer를 가져와 한 번에 보냅니다. 작은 패킷을 자주 보내는 게임 서버에서 packet overhead를 줄이는 용도로 설계되었습니다.

9. UDP 흐름

UDP 모드는 TCP처럼 연결 소켓이 생기지 않지만, 라이브러리는 원격 엔드포인트 또는 패킷 안의 session id를 기준으로 UdpSocketSession과 AppSession을 만들어 TCP와 유사한 애플리케이션 모델을 제공합니다.

SessionID 없는 UDP

remoteEndPoint.ToString()을 session id로 사용합니다. 같은 IP:Port에서 온 datagram은 같은 세션으로 처리됩니다.

UdpRequestInfo 기반 UDP

TRequestInfo가 UdpRequestInfo 계열이면 필터가 패킷에서 SessionID를 추출합니다.

UdpSocketListener.ReceiveFromAsync()
  -> OnNewClientAcceptedAsync(socket, [receivedData, remoteAddress])
  -> UdpSocketServer.OnNewClientAccepted()
  -> ProcessPackageWithSessionID() or ProcessPackageWithoutSessionID()
  -> CreateNewSession() if needed
  -> AppSession.ProcessRequest(...) or IRequestHandler.ExecuteCommand(...)
UDP의 UdpSocketSession.SendAsync()는 listener socket의 SendToAsync()를 사용합니다. 세션의 RemoteEndPoint가 클라이언트 주소 역할을 합니다.

10. 세션 생명주기와 상태 머신

세션은 애플리케이션 관점의 AppSession과 소켓 관점의 SocketSession으로 나뉩니다. AppSession은 사용자 이벤트와 요청 처리를 담당하고, SocketSession은 송수신 상태와 close race를 관리합니다.

생성

AppServer.CreateAppSession()에서 세션 객체를 만들고 Initialize()로 서버, 소켓 세션, 필터를 연결합니다.

실행

SocketSession.Start()가 시작되면 AppSession.StartSession()이 호출되고, 사용자 확장 지점인 OnSessionStarted()가 실행됩니다.

종료

CloseReason과 상태 플래그로 송신 중 종료, 수신 중 종료, 강제 종료를 구분하고, 마지막에 Closed 이벤트를 발행합니다.

SocketSession 상태 플래그

플래그 의미 사용 위치
InSending 현재 socket send 작업이 진행 중 StartSend(), OnSendingCompleted(), Close()
InReceiving 현재 receive 작업이 진행 중 OnReceiveStarted(), OnReceiveEnded()
InClosing 종료 절차 진입 새 receive 시작 차단, 송신 완료 후 실제 close 결정
Closed 닫힘 이벤트까지 처리됨 중복 close 방지, queue 반환

11. 확장 포인트

일반적인 서버 개발에서는 소켓 엔진을 직접 수정하기보다 아래 확장 지점을 사용합니다. 이 경계가 유지되면 프로토콜, 비즈니스 로직, 네트워크 I/O가 분리됩니다.

서버 클래스

AppServer<TSession,TRequestInfo>를 상속하고 생성자에서 receive filter factory와 이벤트를 등록합니다.

class MainServer : AppServer<NetworkSession, EFBinaryRequestInfo>
{
    public MainServer()
        : base(new DefaultReceiveFilterFactory<ReceiveFilter, EFBinaryRequestInfo>())
    {
        NewSessionConnected += OnConnected;
        SessionClosed += OnClosed;
        NewRequestReceived += RequestReceived;
    }
}

세션 클래스

AppSession<TSession,TRequestInfo>를 상속해 사용자별 상태, 인증 상태, 현재 방, 캐릭터 id 같은 정보를 붙입니다.

public class NetworkSession
    : AppSession<NetworkSession, EFBinaryRequestInfo>
{
    public long UserId { get; set; }
}

요청 정보

IRequestInfo 또는 BinaryRequestInfo 계열로 패킷 id, type, body를 표현합니다.

수신 필터

게임 서버에서는 FixedHeaderReceiveFilter로 [size][packetId][type][body] 같은 헤더 기반 프로토콜을 구현하는 패턴이 많습니다.

12. 설정 모델

ServerConfig는 네트워크 동작과 내부 풀 크기를 결정합니다. 운영 서버에서는 기본값을 그대로 쓰기보다 연결 수, 패킷 크기, 송신 패턴에 맞게 조정해야 합니다.

설정 기본값 또는 역할 영향
Mode 기본 SocketMode.Tcp SocketServerFactory가 TCP/UDP 서버 구현을 선택합니다.
MaxConnectionNumber 기본 100 SAEA 풀 크기, UDP 연결 수 제한, 전체 동시 연결 한계에 영향을 줍니다.
ReceiveBufferSize 기본 4096 Pipe segment 크기와 UDP receive buffer 크기에 사용됩니다.
MaxRequestLength 기본 1024 필터가 누적한 요청 길이가 이 값을 넘으면 프로토콜 오류로 닫힙니다.
SendingQueueSize 기본 5 한 큐에 담을 수 있는 ArraySegment<byte> 개수를 결정합니다.
SyncSend 기본 false true면 Socket.Send(), false면 Socket.SendAsync()를 사용합니다.
CollectSendIntervalMillSec 기본 0 0보다 크면 세션별 데이터를 모았다가 타이머로 일괄 송신합니다.
PreAllocateSAEA 기본 true true면 시작 시 최대 연결 수만큼 SAEA를 미리 만들고, false면 MinPoolSize에서 시작해 동적으로 증가합니다.
NoDelay 기본 false TCP Nagle 알고리즘 사용 여부에 영향을 줍니다. 실시간 게임 패킷은 요구사항에 따라 조정합니다.

13. 성능 설계 포인트

객체 풀링

SmartPool<SocketAsyncEventArgsProxy>, SmartPool<SocketAsyncEventArgs>, SmartPool<SendingQueue>가 연결과 송신 시 반복 할당을 줄입니다.

Pipelines 기반 수신

수신 완료 콜백은 PipeWriter에 쓰고, 파싱은 PipeReader 루프에서 진행합니다. I/O 완료 처리와 애플리케이션 처리를 분리하는 구조입니다.

세션 스냅샷

DisableSessionSnapshot이 false면 주기적으로 ConcurrentDictionary를 배열 스냅샷으로 떠서 전체 세션 순회 비용을 예측 가능하게 만듭니다.

부분 패킷 처리

기존 필터와 Pipelines를 연결하기 위해 AppSession은 세션별 ArrayPool<byte> carry buffer를 유지합니다.

성능 설정은 트래픽 형태와 패킷 크기에 따라 달라집니다. 예를 들어 작은 패킷이 매우 잦으면 collect-send가 유리할 수 있지만, 즉시성이 더 중요하면 지연을 늘리는 설정이 될 수 있습니다.

14. 예제 서버에 적용해서 보기

Tutorials/EchoServer/MainServer.cs는 라이브러리 사용법을 잘 보여주는 예입니다. 서버는 AppServer<NetworkSession,EFBinaryRequestInfo>를 상속하고, DefaultReceiveFilterFactory<ReceiveFilter,EFBinaryRequestInfo>를 넘겨 바이너리 프로토콜을 사용합니다.

MainServer 생성자
필터 팩토리를 지정하고 NewSessionConnected, SessionClosed, NewRequestReceived 이벤트를 등록합니다.
InitConfig
ServerConfig에 port, ip, max connection, mode, name을 채웁니다.
CreateServer
Setup(new RootConfig(), _config, logFactory: new ConsoleLogFactory())로 서버를 구성합니다.
RequestReceived
요청 body 길이와 packet id를 읽고 같은 body를 다시 패킹해 session.Send()로 echo 응답을 보냅니다.

처음 코드를 읽는다면 아래 순서로 보는 것이 가장 빠릅니다. 애플리케이션 API에서 시작해 엔진 내부로 내려가면 각 책임이 자연스럽게 이어집니다.

  3. SuperSocketLite/SocketBase/AppSession.cs: 세션 API, 수신 필터 호출, 요청 루프, Send API가 있습니다.
  4. SuperSocketLite/SocketServerFactory.cs: TCP/UDP 구현 선택 지점입니다.
  5. SuperSocketLite/AsyncSocketServer.cs: TCP 연결 수락 후 SAEA 풀과 세션 생성 흐름입니다.
  6. SuperSocketLite/AsyncSocketSession.cs: TCP receive/send의 실제 비동기 구현입니다.
  7. SuperSocketLite/SocketSession.cs: 공통 세션 상태 머신, SendingQueue, PipeReader 루프가 있습니다.
  8. SuperSocketLite/TcpAsyncSocketListener.cs: TCP accept loop입니다.
  9. SuperSocketLite/UdpSocketListener.cs: UDP ReceiveFromAsync loop입니다.
  10. SuperSocketLite/UdpSocketServer.cs: UDP datagram을 AppSession 모델로 연결합니다.

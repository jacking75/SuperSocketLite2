SuperSocketLite 2 전체 아키텍처

SuperSocketLite는 AppServer, SocketServer, SocketSession, AppSession, IReceiveFilter를 중심으로 TCP/UDP 서버를 구성하는 비동기 I/O 라이브러리입니다. 이 문서는 현재 코드 기준의 receive pipe, sequence filter, Channel 기반 송신 큐, UDP packet 수명 관리를 설명합니다.

1. 주요 계층

영역대표 타입역할
애플리케이션 AppServer<TSession,TRequestInfo>, AppSession 세션 생성, 이벤트, command 실행, collect-send timer, raw data hook을 담당합니다.
서버 엔진 AsyncSocketServer, UdpSocketServer, SocketServerBase TCP/UDP 구현 선택, listener 시작/중지, socket session 생성을 담당합니다.
세션 SocketSession, AsyncSocketSession, UdpSocketSession receive pipe, send queue, close 상태 머신, 실제 socket send/receive를 관리합니다.
프로토콜 IReceiveFilter, ISequenceReceiveFilter, FixedHeaderReceiveFilter 바이트 스트림 또는 ReadOnlySequence<byte>를 request 객체로 변환합니다.

2. TCP 수신 구조

TCP 수신은 AsyncSocketSession이 생산자, SocketSession.ProcessPipeAsync()가 소비자인 구조입니다. receive 완료 콜백은 받은 바이트 수만큼 PipeWriter.Advance()와 FlushAsync()를 호출하고, 별도 task가 PipeReader.ReadAsync() 결과를 AppSession.ProcessRequest()로 넘깁니다. 

Socket.ReceiveAsync
  -> AsyncSocketSession.ProcessReceive()
  -> PipeWriter.Advance(bytes)
  -> PipeWriter.FlushAsync()
  -> SocketSession.ProcessPipeAsync()
  -> AppSession.ProcessRequest(ReadOnlySequence<byte>)
  -> ReceiveFilter
  -> AppServer.ExecuteCommand()

AppSession.ProcessRequest(ReadOnlySequence<byte>)는 ProcessReceiveResult를 반환합니다. SocketSession은 이 값의 Consumed와 Examined를 사용해 PipeReader.AdvanceTo()를 호출합니다.

3. ReceiveFilter 경로

기존 byte[] 필터

IReceiveFilter<TRequestInfo>만 구현한 필터는 호환 경로를 탑니다. AppSession은 pipe의 ReadOnlySequence를 세션별 carry buffer에 복사한 뒤 기존 Filter(byte[])를 호출합니다.

Sequence 필터

ISequenceReceiveFilter<TRequestInfo>를 구현하면 ReadOnlySequence<byte>를 직접 파싱합니다. raw-data handler가 등록된 서버에서는 raw hook 보장을 위해 기존 byte[] 경로가 사용됩니다.

FixedSizeReceiveFilter와 FixedHeaderReceiveFilter는 sequence 경로를 지원합니다. FixedHeaderSequenceReceiveFilter는 헤더와 바디를 복사하지 않고 sequence slice로 request를 만들 수 있는 opt-in 기반 클래스이며, byte[] fallback에서는 fragmented packet을 내부 buffer에 누적합니다.

4. 송신 구조

활성 송신 경로는 세션별 ChannelSendingQueue를 사용합니다. Config.SendingQueueSize는 bounded channel capacity로 쓰이며, 송신권은 SocketState.InSending flag로 세션당 하나만 허용합니다. 

AppSession.Send(...)
  -> SocketSession.TrySend(...)
  -> ChannelSendingQueue.TryEnqueue(...)
  -> StartSend(initial: true)
  -> ChannelSendingQueue.DrainAvailable()
  -> SendAsync(items) or SendSync(items)
  -> OnSendingCompleted(items)
  -> queued item이 있으면 StartSend(initial: false)

ChannelSendingQueue는 완료 flag와 lock으로 Complete()와 batch enqueue의 경합을 막습니다. 따라서 close 중에 multi-segment send의 일부만 queue에 들어가는 상태를 만들지 않습니다.

SuperSocketLite.Common.SendingQueue와 SendingQueueSourceCreator는 legacy 타입으로 남아 있지만, SocketServerBase는 더 이상 SmartPool<SendingQueue>를 초기화하지 않습니다. 명시적 ISocketServer.SendingQueuePool 구현은 호환성 목적으로 null을 반환합니다.

5. UDP 구조

UDP listener는 receive buffer를 ArrayPool<byte>에서 대여합니다. datagram을 받으면 현재 buffer를 UdpReceivePacket에 넘기고 즉시 다음 receive용 buffer를 새로 대여합니다. endpoint는 IPEndPoint 값으로 snapshot되므로 이후 SocketAsyncEventArgs.RemoteEndPoint 재사용과 분리됩니다. 

UdpSocketListener.ReceiveFromAsync()
  -> UdpReceivePacket(buffer, offset, count, endpoint snapshot)
  -> UdpSocketServer.OnNewClientAccepted()
  -> datagram별 ReceiveFilter 생성
  -> AppSession.ProcessRequest(...) 또는 command 실행
  -> UdpReceivePacket.Dispose()로 ArrayPool 반환

UDP payload는 zero-copy로 filter와 handler에 전달됩니다. handler 이후에는 buffer가 pool로 반환되므로, request나 사용자 코드가 payload를 장기 보관해야 한다면 자체적으로 복사해야 합니다.

6. Collect Send

CollectSendIntervalMillSec > 0이면 세션은 ReuseLockBaseBuffer에 작은 송신을 모읍니다. timer는 세션별 buffer snapshot을 만든 뒤 session.Send(snapshot)을 호출하고, 성공 여부와 관계없이 읽은 길이만큼 CommitCollectSend()를 수행합니다. AppServer.Stop()은 collect-send timer를 중지하고 dispose합니다.

7. 설정 영향

설정현재 의미
ReceiveBufferSizeTCP pipe segment 최소 크기, UDP receive buffer 크기, collect-send buffer 크기에 사용됩니다.
SendingQueueSize세션별 ChannelSendingQueue bounded capacity입니다.
MaxRequestLengthbyte[] carry 경로와 sequence 경로에서 protocol error 판단에 사용됩니다.
SyncSend동기 socket send를 사용할지 결정합니다. 동기 경로도 partial send를 반복 처리합니다.
CollectSendIntervalMillSec작은 송신을 모아 보내며, 이때 세션 송신은 동기 모드로 전환됩니다.

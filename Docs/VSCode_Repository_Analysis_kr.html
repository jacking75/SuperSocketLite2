VS Code 저장소 전체 분석

VS Code C# 언어 서버가 루트 통합 솔루션 SuperSocketLite2.slnx를 로드하도록 설정하는 방법을 설명합니다. 이 솔루션에는 라이브러리, 템플릿, 테스트, 튜토리얼을 포함한 C# 프로젝트 33개가 등록되어 있습니다.

1. 설정이 필요한 이유

확인한 C# 확장의 standalone 모드는 기본 솔루션을 자동 선택할 때 .sln 파일을 검색합니다. 이 저장소의 통합 솔루션은 루트의 .slnx이고 하위 디렉터리에는 여러 .sln이 있으므로, 기본 솔루션을 지정하지 않으면 원하는 통합 솔루션이 자동으로 선택되지 않을 수 있습니다.

솔루션이 선택되지 않은 상태에서 C# 파일을 열면 Roslyn은 해당 파일들을 임시 Canonical.csproj에 넣어 분석합니다. 이 방식은 파일 단위 편집에는 사용할 수 있지만 저장소 전체의 프로젝트 관계와 모든 소스 파일을 제공하지 않습니다.

2. 작업 영역 설정

저장소 루트에 .vscode/settings.json을 만들고 다음 내용을 저장합니다.

{
  "dotnet.defaultSolution": "SuperSocketLite2.slnx"
}
.vscode/는 현재 .gitignore 대상입니다. 따라서 이 설정은 저장소를 사용하는 각 컴퓨터에서 로컬로 만들어야 합니다. 저장소 전체 대신 핵심 라이브러리만 분석하려면 값으로 SuperSocketLite/SuperSocketLite.sln을 사용할 수 있습니다.

3. 설정 적용

  1. VS Code에서 C:\github_dev\SuperSocketLite2처럼 저장소 루트를 작업 영역으로 엽니다.
  2. 작업 영역을 신뢰한 상태인지 확인합니다. 제한 모드에서는 C# 확장이 limited mode로 실행됩니다.
  3. 명령 팔레트에서 개발자: 창 다시 로드를 실행합니다.
  4. 솔루션과 NuGet 복원이 끝날 때까지 기다린 뒤 F12를 다시 실행합니다.

4. 정상 로드 확인

보기 → 출력에서 출력 채널을 C#으로 바꾸고 로드 메시지를 확인합니다.

로그 상태의미
SuperSocketLite2.slnx와 여러 프로젝트를 로드저장소 전체 분석이 활성화된 정상 상태입니다.
Canonical.csproj만 로드통합 솔루션이 선택되지 않아 열어 본 파일만 분석하는 상태입니다.
limited mode작업 영역 신뢰가 허용되지 않은 상태입니다.

5. F12가 일부 심볼에서만 동작하는 경우

현상가능한 이유확인 방법
같은 파일의 정의는 이동되지만 다른 파일은 이동되지 않음 임시 Canonical.csproj가 열린 파일만 알고 있습니다. C# 출력 로그에서 실제 통합 솔루션이 로드됐는지 확인합니다.
Task, Socket 등은 이동되지만 저장소 타입은 실패함 .NET 참조 어셈블리는 로드됐지만 저장소 프로젝트는 로드되지 않았습니다. dotnet.defaultSolution과 창 재로드 여부를 확인합니다.
인터페이스 메서드의 선언으로만 이동함 F12는 정적 타입 기준 정의를 반환합니다. VS Code의 구현으로 이동 기능으로 실제 구현 후보를 확인합니다.

6. 솔루션 등록 확인

터미널에서 다음 명령을 실행하면 통합 솔루션에 포함된 프로젝트를 확인할 수 있습니다.

dotnet sln SuperSocketLite2.slnx list

현재 통합 솔루션에는 C# 프로젝트 33개가 등록되어 있습니다.

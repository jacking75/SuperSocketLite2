수신 파이프라인과 ReceiveFilter

TCP 수신은 System.IO.Pipelines 기반입니다. 기존 IReceiveFilter<TRequestInfo> 경로와 ISequenceReceiveFilter<TRequestInfo> zero-copy 경로를 모두 지원합니다.

1. 전체 흐름

Socket.ReceiveAsync
  -> AsyncSocketSession.ProcessReceive()
  -> PipeWriter.Advance()
  -> PipeWriter.FlushAsync()
  -> SocketSession.ProcessPipeAsync()
  -> AppSession.ProcessRequest(ReadOnlySequence<byte>)
  -> ReceiveFilter
  -> AppServer.ExecuteCommand()

I/O 완료 콜백은 pipe에 받은 바이트를 기록하고 다음 receive를 예약합니다. 요청 파싱과 command 실행은 별도 pipe 처리 task에서 수행됩니다.

2. ProcessPipeAsync()

SocketSession.ProcessPipeAsync()는 PipeReader.ReadAsync()로 읽은 버퍼를 AppSession.ProcessRequest()에 전달합니다. 현재 구현은 consumed와 examined를 함께 담은 ProcessReceiveResult를 반환하므로, sequence filter가 일부 데이터만 소비한 경우 남은 데이터를 즉시 다시 처리할 수 있습니다. 

result = await _pipeReader.ReadAsync();
buffer = result.Buffer;
processResult = AppSession.ProcessRequest(buffer);
_pipeReader.AdvanceTo(processResult.Consumed, processResult.Examined);

파싱 중 예외가 발생하면 CloseReason.ProtocolError로 세션을 닫습니다. pipe loop 종료 시 _pipeReader.Complete()와 AppSession.CompleteReceivePipe()를 호출해 세션별 carry buffer를 반환합니다.

3. 두 가지 필터 경로

호환 byte[] 경로

서버에 RawDataReceived handler가 있거나 현재 필터가 ISequenceReceiveFilter를 구현하지 않으면 이 경로를 탑니다. AppSession은 pipe의 ReadOnlySequence<byte>를 세션별 carry buffer에 복사한 뒤 기존 Filter(byte[])를 호출합니다.

Sequence zero-copy 경로

raw-data handler가 없고 현재 필터가 ISequenceReceiveFilter<TRequestInfo>이면 ReadOnlySequence<byte>를 직접 넘깁니다. incomplete packet은 pipe에 남기고, complete packet만 consumed position을 전진시킵니다.

4. IReceiveFilter 계약

public interface IReceiveFilter<TRequestInfo>
    where TRequestInfo : IRequestInfo
{
    TRequestInfo? Filter(byte[] readBuffer, int offset, int length, bool toBeCopied, out int rest);
    TRequestInfo? Filter(ReadOnlySpan<byte> buffer, bool toBeCopied, out int rest);
    int LeftBufferSize { get; }
    IReceiveFilter<TRequestInfo>? NextReceiveFilter { get; }
    FilterState State { get; }
    void Reset();
}

기존 필터 구현은 이 계약만 지켜도 동작합니다. pipe에서 받은 데이터가 여러 segment로 나뉘면 AppSession이 carry buffer에 복사해 contiguous byte 배열로 만들어 줍니다.

5. ISequenceReceiveFilter 계약

public interface ISequenceReceiveFilter<TRequestInfo> : IReceiveFilter<TRequestInfo>
    where TRequestInfo : IRequestInfo
{
    TRequestInfo? Filter(
        ReadOnlySequence<byte> buffer,
        out SequencePosition consumed,
        out SequencePosition examined);
}

이 API는 pipe의 ReadOnlySequence를 그대로 받습니다. 요청 하나가 완성되면 consumed와 examined를 요청 끝으로 설정합니다. 아직 데이터가 부족하면 consumed는 시작 위치로 유지하고 examined는 확인한 위치까지 설정합니다.

6. FixedSizeReceiveFilter

FixedSizeReceiveFilter<TRequestInfo>는 현재 ISequenceReceiveFilter를 구현합니다. 지정한 크기만큼 데이터가 도착했을 때만 request를 만들고, 부족하면 데이터를 소비하지 않습니다.

7. FixedHeaderReceiveFilter

FixedHeaderReceiveFilter<TRequestInfo>도 sequence 경로를 지원합니다. 헤더로 body 길이를 계산하고 전체 요청이 도착했을 때만 소비합니다. body 길이가 음수이거나 MaxRequestLength를 넘으면 FilterState.Error가 되고 세션은 protocol error로 닫힙니다.

8. FixedHeaderSequenceReceiveFilter

FixedHeaderSequenceReceiveFilter<TRequestInfo>는 sequence 기반 fixed-header 프로토콜을 직접 구현하기 위한 기반 클래스입니다. ResolveRequestInfo(ReadOnlySequence<byte> header, ReadOnlySequence<byte> body) 에서 header/body slice를 복사 없이 사용할 수 있습니다. 

protected abstract int GetBodyLengthFromHeader(ReadOnlySequence<byte> header);
protected abstract TRequestInfo? ResolveRequestInfo(
    ReadOnlySequence<byte> header,
    ReadOnlySequence<byte> body);

이 클래스는 legacy byte-array fallback도 제공합니다. byte[] 경로에서 fragmented packet이 들어오면 내부 legacy buffer에 누적했다가 요청이 완성되면 rest를 계산하고 누적 버퍼를 반환합니다.

9. RawDataReceived와 zero-copy의 관계

RawDataReceived handler는 기존 byte[] raw hook 호출을 보장해야 합니다. 따라서 이 handler가 등록된 서버에서는 필터가 ISequenceReceiveFilter를 구현하더라도 AppSession이 byte[] carry 경로를 사용합니다. body 복사를 피하는 것이 더 중요하면 raw hook을 등록하지 않는 구성이 적합합니다.

10. MaxRequestLength

경로검사 시점
byte[] carry 경로 새 bytes를 carry buffer에 복사하기 전에 writeOffset + sequence.Length를 검사합니다.
sequence 경로 ProcessSequenceRequest()와 각 sequence filter가 sequence/request 길이를 검사합니다.

11. 구현 체크리스트

새 프로토콜에서 body 복사를 줄이고 싶다면 ISequenceReceiveFilter 또는 FixedHeaderSequenceReceiveFilter를 선택하십시오. raw byte hook이 필요한 서버에서는 기존 IReceiveFilter 경로가 더 적합합니다.

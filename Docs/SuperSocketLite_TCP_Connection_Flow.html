TCP 연결 흐름

TCP 서버가 시작되고 client socket을 accept한 뒤 AsyncSocketSession, AppSession, receive pipe, send queue가 준비되는 순서를 설명합니다.

1. 서버 시작

AppServer.Start()는 설정을 확정한 뒤 SocketServerFactory를 통해 TCP 또는 UDP 서버 구현을 만듭니다. TCP에서는 AsyncSocketServer와 TcpAsyncSocketListener가 사용됩니다. 

AppServer.Start()
  -> SocketServerFactory.CreateSocketServer(...)
  -> AsyncSocketServer.Start()
  -> SocketServerBase.Start()
  -> TcpAsyncSocketListener.Start()
  -> AcceptLoopAsync()

현재 SocketServerBase.Start()는 listener 생성과 시작을 담당합니다. 이전 구현처럼 SmartPool<SendingQueue>를 초기화하지 않습니다. 송신 큐는 각 SocketSession.Initialize()에서 세션별 ChannelSendingQueue로 생성됩니다.

2. Accept와 SocketSession 생성

TcpAsyncSocketListener는 accept한 client socket을 NewClientAccepted 이벤트로 전달합니다. AsyncSocketServer.ProcessNewClient()는 receive용 SocketAsyncEventArgsProxy와 send용 SocketAsyncEventArgs를 준비한 뒤 AsyncSocketSession을 생성합니다. 

TcpAsyncSocketListener.AcceptLoopAsync()
  -> OnNewClientAccepted(client, null)
  -> AsyncSocketServer.ProcessNewClient(client)
  -> new AsyncSocketSession(client, receiveSAEA, sendSAEA)
  -> TcpSocketServerBase.CreateSession(socketSession)
  -> AppServer.CreateAppSession()
  -> AppSession.Initialize(appServer, socketSession)
  -> SocketSession.Initialize(appSession)

3. SocketSession.Initialize()

세션 초기화에서는 설정을 보관하고 송신 큐, collect-send buffer, receive pipe를 준비합니다. 

public virtual void Initialize(IAppSession appSession)
{
    AppSession = appSession;
    Config = appSession.Config;
    SyncSend = Config.SyncSend;

    m_SendQueue = new ChannelSendingQueue(Math.Max(Config.SendingQueueSize, 1));

    if (Config.CollectSendIntervalMillSec > 0)
    {
        CollectSendBuffer = new ReuseLockBaseBuffer(Config.ReceiveBufferSize);
        SyncSend = true;
    }

    var pipeOptions = new PipeOptions(
        minimumSegmentSize: Config.ReceiveBufferSize,
        useSynchronizationContext: false);
    _receivePipe = new Pipe(pipeOptions);
    _pipeWriter = _receivePipe.Writer;
    _pipeReader = _receivePipe.Reader;
}

4. 세션 등록과 시작

AppServer.RegisterSession()이 성공하면 socket session을 시작합니다. AsyncSocketSession.Start()는 첫 receive를 게시하고 pipe 처리 task를 저장한 뒤 app session 시작 이벤트를 호출합니다. 

AsyncSocketSession.Start()
  -> StartReceive()
  -> StartReceiveProcessingTask()
  -> StartSession()
  -> AppSession.StartSession()
  -> OnSessionStarted()

StartReceiveProcessingTask()는 m_ReceiveProcessingTask = ProcessPipeAsync()를 저장합니다. close 시점에는 이 task를 한 번만 관찰해 background exception이 조용히 사라지지 않도록 합니다.

5. ReceiveAsync 이후

StartReceive()는 PipeWriter.GetMemory(Config.ReceiveBufferSize)로 받은 memory를 receive SAEA buffer로 설정합니다. 완료 콜백은 받은 byte 수만큼 writer를 전진시키고 flush 결과에 따라 다음 receive를 예약합니다. 

StartReceive()
  -> _pipeWriter.GetMemory(...)
  -> SocketAsyncEventArgs.SetBuffer(memory)
  -> Socket.ReceiveAsync(...)

ProcessReceive()
  -> _pipeWriter.Advance(e.BytesTransferred)
  -> _pipeWriter.FlushAsync()
  -> StartReceive() 또는 flush continuation

6. Pipe 소비와 요청 실행

ProcessPipeAsync()는 PipeReader.ReadAsync()로 읽은 ReadOnlySequence<byte>를 AppSession.ProcessRequest()에 넘깁니다. protocol parsing에서 예외가 발생하면 CloseReason.ProtocolError로 닫습니다. 

ProcessPipeAsync()
  while true:
    result = await _pipeReader.ReadAsync()
    processResult = AppSession.ProcessRequest(result.Buffer)
    _pipeReader.AdvanceTo(processResult.Consumed, processResult.Examined)
  finally:
    _pipeReader.Complete()
    AppSession.CompleteReceivePipe()

ProcessReceiveResult는 consumed와 examined를 모두 담습니다. sequence filter가 현재 buffer의 일부만 소비하면 examined도 소비 위치로 맞춰 남은 데이터를 즉시 다시 처리합니다.

7. Close 경로

close가 시작되면 socket 상태 flag를 갱신하고 receive pipe writer를 완료합니다. 송신 큐는 ChannelSendingQueue.Complete()로 닫혀 이후 enqueue를 막습니다.

상황동작
원격 close 또는 receive 0 byteCloseReason.RemoteClosing 계열로 닫고 pipe writer를 완료합니다.
protocol errorProcessPipeAsync()가 예외를 기록하고 CloseReason.ProtocolError로 닫습니다.
send 중 close남은 송신 데이터가 있으면 완료 콜백에서 다음 batch를 보낸 뒤 close 이벤트를 발행합니다.

8. 체크 포인트

TCP 연결 흐름을 확인할 때는 AsyncSocketServer.cs, TcpAsyncSocketListener.cs, AsyncSocketSession.cs, SocketSession.cs, AppSession.cs를 함께 보십시오. 송신 큐 pool 설명이 보이면 낡은 설명입니다. 현재는 세션별 ChannelSendingQueue가 기준입니다.

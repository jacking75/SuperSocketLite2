SuperSocketLite 2 송신 파이프라인과 SendingQueue 상세 해설

이 문서는 기존 SuperSocketLite_Architecture.html의 8장 내용을 별도 HTML로 확장한 것입니다. 송신을 이해하는 데 필요한 6장 수신 파이프라인과 7장 ReceiveFilter 흐름을 먼저 짧게 정리한 뒤, AppSession.Send()에서 Socket.SendAsync() 완료 콜백까지 코드 중심으로 추적합니다.

대상: 모바일 게임 서버 TCP 송신 경로 핵심: 단일 송신권 + 이중 SendingQueue 코드 기준: .NET 10.0 프로젝트 아래쪽에 함수 호출 탐색기 포함

6. 수신 파이프라인: 송신과 대비되는 입력 경로

송신 파이프라인은 큐를 중심으로 “나가는 데이터”를 직렬화합니다. 반대로 수신 파이프라인은 SocketAsyncEventArgs와 PipeWriter/PipeReader를 통해 “들어오는 데이터”를 프로토콜 파서로 넘깁니다. 두 경로를 나란히 보면 송신 쪽의 SendingQueue가 왜 필요한지 더 분명해집니다.

ReceiveAsync 완료

AsyncSocketSession.ProcessReceive()가 BytesTransferred를 확인하고 PipeWriter에 기록합니다.

PipeReader 소비

SocketSession의 PipeReader 루프가 버퍼를 읽고 AppSession.ProcessRequest()로 넘깁니다.

요청 핸들러

요청 처리 중 응답을 보내면 다시 session.Send(...)가 호출되어 송신 파이프라인으로 진입합니다.

7. ReceiveFilter와 요청 처리: 응답 송신의 출발점

ReceiveFilter는 byte stream을 IRequestInfo로 변환합니다. 게임 서버에서는 요청 핸들러가 처리 결과를 만든 뒤 AppSession.Send() 또는 TrySend()를 호출하는 경우가 많습니다. 따라서 7장은 8장의 바로 앞 단계입니다.

요청 처리에서 송신으로 이어지는 모양

AppSession.cs 
ProcessRequest(ReadOnlySequence<byte> buffer)
  -> FilterRequest(...)
     -> m_ReceiveFilter.Filter(...)
  -> AppServer.ExecuteCommand(this, requestInfo)
     -> NewRequestReceived(session, requestInfo)
        -> session.Send(responseBytes)
수신 쪽 관심사 패킷 경계 찾기, 부분 패킷 보존, 프로토콜 오류 차단, 요청 객체 생성입니다.
송신 쪽 관심사 여러 스레드의 응답 데이터를 하나의 socket send 흐름으로 직렬화하고, 부분 송신과 close 상태를 처리하는 것입니다.
핵심 연결점 요청 핸들러는 AppSession만 보지만 실제 제어는 SocketSession과 SendingQueue가 담당합니다.

8. 송신 파이프라인 큰 흐름

송신은 공개 API인 AppSession.Send()/TrySend()에서 시작됩니다. AppSession은 연결 상태와 재시도 정책을 담당하고, SocketSession은 현재 쓰기 가능한 SendingQueue에 데이터를 넣은 뒤 송신권을 얻어 실제 socket send를 시작합니다.

1. enqueue

SocketSession.TrySend()가 현재 m_SendingQueue를 읽고, 같은 TrackID일 때만 데이터를 넣습니다.

2. 송신권 획득

StartSend(..., initial: true)가 SocketState.InSending 플래그를 잡아 중복 송신 시작을 막습니다.

3. 큐 교체

보낼 큐는 read-only로 잠그고, 새 큐를 m_SendingQueue에 연결해 이후 enqueue를 받게 합니다.

AppSession Send API: 사용자 코드가 보는 표면

사용자 코드가 직접 만나는 API는 AppSession입니다. TrySend()는 큐에 넣지 못하면 바로 false를 반환합니다. Send()는 InternalSend()로 들어가며, 큐가 꽉 찼거나 잠시 교체 중이면 Config.SendTimeOut 정책에 따라 재시도합니다.

{
    if (!m_Connected)
        return;

        return;

    if (sendTimeOut < 0)
    {
        throw new TimeoutException("The sending attempt timed out");
    }

    var timeOutTime = sendTimeOut > 0 ? DateTime.Now.AddMilliseconds(sendTimeOut) : DateTime.Now;
    var spinWait = new SpinWait();

    while (m_Connected)
    {
        spinWait.SpinOnce();

        if (InternalTrySend(segment))
            return;

        if (sendTimeOut > 0 && DateTime.Now >= timeOutTime)
        {
            throw new TimeoutException("The sending attempt timed out");
        }
    }
}
해석: Send()가 “socket send 완료까지 기다린다”는 뜻은 아닙니다. 큐에 넣는 데 성공할 때까지 기다리는 API입니다. 실제 네트워크 송신 완료는 뒤에서 OnSendingCompleted()로 처리됩니다.

SocketSession.TrySend와 StartSend: 큐 스왑의 핵심

SocketSession은 세션당 하나의 m_SendingQueue를 현재 enqueue 대상으로 유지합니다. TrySend()는 이 큐에 데이터를 넣고, StartSend()는 “이 큐를 이제 보낼 큐로 고정”합니다. 이때 새 큐를 pool에서 꺼내 m_SendingQueue로 바꾸므로, 송신 중에도 다른 스레드가 다음 데이터를 계속 enqueue할 수 있습니다.

TrySend: 현재 큐에 넣고 송신 시작 시도

코드 왜 필요한가 실패하면

trackID 큐가 clear 후 재사용된 경우, 오래된 스레드가 잘못 enqueue하지 못하게 합니다. Enqueue() 실패
StartSend(..., true) 실제로 송신 중이 아니면 이 호출자가 송신권을 얻습니다. 이미 다른 송신자가 있으면 조용히 반환

StartSend: 송신권, 새 큐 확보, CompareExchange

SocketSession.cs:349 
private void StartSend(SendingQueue queue, int sendingTrackID, bool initial)
{
    if (initial)
    {
        if (!TryAddStateFlag(SocketState.InSending))
        {
            return;
        }

        var currentQueue = m_SendingQueue;

        if (currentQueue != queue || sendingTrackID != currentQueue.TrackID)
        {
            //Has been sent
            OnSendEnd();
            return;
        }
    }

    Socket? client;

    if (IsInClosingOrClosed && TryValidateClosedBySocket(out client))
    {
        OnSendEnd();
        return;
    }

    SendingQueue? newQueue;

    if (!m_SendingQueuePool.TryGet(out newQueue))
    {
        OnSendEnd(CloseReason.InternalError, true);
        AppSession.Logger.Error("There is no enougth sending queue can be used.");
        return;
    }

    var oldQueue = Interlocked.CompareExchange(ref m_SendingQueue, newQueue, queue);

    if (!ReferenceEquals(oldQueue, queue))
    {
        if (newQueue != null)
            m_SendingQueuePool.Push(newQueue);

        if (IsInClosingOrClosed)
            OnSendEnd();
        else
            OnSendEnd(CloseReason.InternalError, true);

        return;
    }

    newQueue!.StartEnqueue();
    queue.StopEnqueue();

    if (queue.Count == 0)
    {
        m_SendingQueuePool.Push(queue);
        OnSendEnd(CloseReason.InternalError, true);
        AppSession.Logger.Error("There is no data to be sent in the queue.");
        return;
    }

    Send(queue);
}

initial == true

TrySend()에서 처음 호출할 때입니다. SocketState.InSending 플래그를 잡은 호출자만 실제 송신을 시작합니다.

initial == false

완료 콜백에서 다음 큐를 바로 이어 보낼 때입니다. 이미 송신 흐름 안에 있으므로 InSending을 다시 잡지 않습니다.

SendingQueue 내부: lock 대신 CAS와 read-only 전환

SendingQueue는 IList<ArraySegment<byte>>처럼 보이지만 일반 리스트가 아닙니다. pool이 제공한 큰 ArraySegment<byte>[] 배열의 일부 구간을 자기 큐처럼 사용합니다. enqueue는 Interlocked.CompareExchange로 슬롯 수를 예약하고, 실제 socket send 시점에는 StopEnqueue()로 더 이상 쓰지 못하게 합니다.

Enqueue: 슬롯 예약 후 배열에 기록

SendingQueue.cs:54 SendingQueue.cs:89 
private bool TryEnqueue(ArraySegment<byte> item, out bool conflict, ushort trackID)
{
    conflict = false;

    var oldCount = m_CurrentCount;

    if (oldCount >= Capacity)
        return false;

    if (m_ReadOnly)
        return false;

    if (trackID != m_TrackID)
        return false;

    int compareCount = Interlocked.CompareExchange(ref m_CurrentCount, oldCount + 1, oldCount);

    if (compareCount != oldCount)
    {
        conflict = true;
        return false;
    }

    m_GlobalQueue[m_Offset + oldCount] = item;
    return true;
}

public bool Enqueue(ArraySegment<byte> item, ushort trackID)
{
    if (m_ReadOnly)
        return false;

    Interlocked.Increment(ref m_UpdatingCount);

    while (!m_ReadOnly)
    {
        bool conflict = false;

        if (TryEnqueue(item, out conflict, trackID))
        {
            Interlocked.Decrement(ref m_UpdatingCount);
            return true;
        }

        if (!conflict)
            break;
    }

    Interlocked.Decrement(ref m_UpdatingCount);
    return false;
}

핵심 포인트: StopEnqueue()는 단순히 플래그만 바꾸지 않습니다. 이미 Enqueue() 안으로 들어와 슬롯을 예약했지만 아직 배열에 쓰는 중일 수 있는 스레드를 m_UpdatingCount로 기다립니다. 그래서 실제 socket send는 안정된 스냅샷 큐를 대상으로 진행됩니다.

완료, 부분 송신, 다음 큐 이어 보내기

Socket.SendAsync()는 요청한 모든 byte를 항상 한 번에 보냈다고 보장하지 않습니다. AsyncSocketSession.OnSendingCompleted()는 실제 전송 byte 수를 확인하고, 덜 보냈으면 InternalTrim()으로 이미 전송된 앞부분을 잘라낸 뒤 같은 큐를 다시 보냅니다.

SocketAsyncEventArgs 완료 콜백

AsyncSocketSession.cs:89 
void OnSendingCompleted(object? sender, SocketAsyncEventArgs e)
{
    var queue = e.UserToken as SendingQueue;

    if (!ProcessCompleted(e))
    {
        ClearPrevSendState(e);
        OnSendError(queue!, CloseReason.SocketError);
        return;
    }

    var count = queue!.Sum(q => q.Count);

    if (count != e.BytesTransferred)
    {
        queue!.InternalTrim(e.BytesTransferred);
        AppSession.Logger.Info($"{e.BytesTransferred} of {count} were transferred, send the rest {queue.Sum(q => q.Count)} bytes right now.");
        ClearPrevSendState(e);
        SendAsync(queue);
        return;
    }

    ClearPrevSendState(e);
    base.OnSendingCompleted(queue!);
}

{
    queue.Clear();

    {
        Socket? client;

        if (newQueue.Count > 0 && !TryValidateClosedBySocket(out client))
        {
            StartSend(newQueue, newQueue.TrackID, false);
            return;
        }

        OnSendEnd();
        return;

    if (newQueue.Count == 0)
    {
        OnSendEnd();

        if (newQueue.Count > 0)

            StartSend(newQueue, newQueue.TrackID, true);
        }
    }
    else
    {
        StartSend(newQueue, newQueue.TrackID, false);
    }
}

Clear와 InternalTrim

SendingQueue.cs:353 SendingQueue.cs:449 
public void Clear()
{
    if (m_TrackID >= ushort.MaxValue)
        m_TrackID = 1;
    else
        m_TrackID++;

    for (var i = 0; i < m_CurrentCount; i++)
    {
        m_GlobalQueue[m_Offset + i] = m_Null;
    }

    m_CurrentCount = 0;
    m_InnerOffset = 0;
    Position = 0;
}

public void InternalTrim(int offset)
{
    var innerCount = m_CurrentCount - m_InnerOffset;
    var subTotal = 0;

    for (var i = m_InnerOffset; i < innerCount; i++)
    {
        var segment = m_GlobalQueue[m_Offset + i];
        subTotal += segment.Count;

        if (subTotal <= offset)
            continue;

        m_InnerOffset = i;

        var rest = subTotal - offset;
        m_GlobalQueue[m_Offset + i] =
            new ArraySegment<byte>(segment.Array!, segment.Offset + segment.Count - rest, rest);

        break;
    }
}
주의할 점: OnSendingCompleted()에서 newQueue.Count == 0이라도 OnSendEnd() 직후 다시 newQueue.Count > 0를 확인합니다. 송신 플래그를 내리는 아주 짧은 순간에 다른 스레드가 enqueue했을 수 있기 때문입니다.

송신권을 얻고, 새 큐를 pool에서 꺼내 현재 enqueue 대상으로 교체합니다. 기존 큐는 read-only로 닫은 뒤 실제 send 대상으로 고정합니다.

private void StartSend(SendingQueue queue, int sendingTrackID, bool initial)
{
    if (initial)
    {
        if (!TryAddStateFlag(SocketState.InSending))
            return;

        var currentQueue = m_SendingQueue;

        if (currentQueue != queue || sendingTrackID != currentQueue.TrackID)
        {
            OnSendEnd();
            return;
        }
    }

    SendingQueue? newQueue;

    if (!m_SendingQueuePool.TryGet(out newQueue))
    {
        OnSendEnd(CloseReason.InternalError, true);
        return;
    }

    var oldQueue = Interlocked.CompareExchange(ref m_SendingQueue, newQueue, queue);

    if (!ReferenceEquals(oldQueue, queue))
    {
        m_SendingQueuePool.Push(newQueue);
        OnSendEnd(CloseReason.InternalError, true);
        return;
    }

    newQueue!.StartEnqueue();
    queue.StopEnqueue();

    if (queue.Count == 0)
    {
        m_SendingQueuePool.Push(queue);
        OnSendEnd(CloseReason.InternalError, true);
        return;
    }

    Send(queue);
}

public void InternalTrim(int offset)
{
    var innerCount = m_CurrentCount - m_InnerOffset;
    var subTotal = 0;

    for (var i = m_InnerOffset; i < innerCount; i++)
    {
        var segment = m_GlobalQueue[m_Offset + i];
        subTotal += segment.Count;

        if (subTotal <= offset)
            continue;

        m_InnerOffset = i;

        var rest = subTotal - offset;
        m_GlobalQueue[m_Offset + i] =
            new ArraySegment<byte>(segment.Array!, segment.Offset + segment.Count - rest, rest);

        break;
    }
}

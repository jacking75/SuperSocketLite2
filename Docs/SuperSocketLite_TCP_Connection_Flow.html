SuperSocketLite TCP 접속 흐름 상세 분석

이 문서는 기존 SuperSocketLite_Architecture.html의 “5. TCP 접속 흐름”을 별도 파일로 확장한 것입니다. 서버가 TCP listener를 시작하고, 클라이언트 socket을 accept하고, AsyncSocketSession과 AppSession을 연결하고, 첫 receive를 게시하기까지의 코드를 단계별로 설명합니다.

파일: TcpAsyncSocketListener.cs 파일: AsyncSocketServer.cs 파일: TcpSocketServerBase.cs 파일: AppServerBase.cs 파일: AppSession.cs 파일: AsyncSocketSession.cs

1. 큰 그림

TCP 접속 흐름은 “서버 시작 흐름”과 “새 클라이언트 accept 흐름”이 합쳐진 결과입니다. AppServer.Start()는 socket server를 시작하고, socket server는 listener들을 시작합니다. listener가 새 socket을 받으면 AsyncSocketServer.ProcessNewClient()가 세션을 만들고 등록합니다.

이 문서에서는 크로스플랫폼 관점에서 SocketAsyncEventArgs, AcceptAsync, ReceiveAsync, System.IO.Pipelines라는 .NET API 중심으로 설명합니다.

2. 등장 객체와 책임

객체 파일 TCP 접속에서 맡는 일
AppServerBase<TAppSession,TRequestInfo> SocketBase/AppServerBase.cs 서버 상태를 Running으로 전환하고, socket server 시작과 AppSession 생성/등록 이벤트를 담당합니다.
SocketServerBase SocketServerBase.cs 공통 socket server 기반입니다. 송신 큐 풀을 만들고 listener를 생성/시작합니다.
AsyncSocketServer AsyncSocketServer.cs TCP 서버 구현입니다. receive/send SAEA 풀을 관리하고 새 클라이언트 socket을 session으로 승격합니다.
TcpAsyncSocketListener TcpAsyncSocketListener.cs listen socket을 만들고 AcceptAsync 루프로 새 socket을 받습니다.
TcpSocketServerBase TcpSocketServerBase.cs accepted socket에 send/receive buffer, timeout, keep-alive, no-delay, linger 설정을 적용합니다.
AsyncSocketSession AsyncSocketSession.cs accepted socket의 송수신 상태와 receive/send 비동기 작업을 관리합니다.
AppSession SocketBase/AppSession.cs 사용자가 다루는 세션입니다. receive filter를 보유하고 요청 처리와 송신 API를 제공합니다.

3. Start 단계에서 TCP 접속을 받을 준비

TCP 접속 흐름은 클라이언트가 접속하기 전에 이미 준비됩니다. AppServerBase.Start()가 socket server를 시작하고, TCP 모드의 socket server인 AsyncSocketServer.Start()는 SAEA 풀을 만든 뒤 SocketServerBase.Start()로 listener들을 시작합니다.

3.1 AppServerBase.Start()

Start()는 서버 상태를 NotStarted에서 Starting으로 바꾼 뒤 내부 socket server를 시작합니다. 성공하면 StartedTime을 기록하고 상태를 Running으로 바꿉니다. 

public virtual bool Start()
{
    var origStateCode = Interlocked.CompareExchange(
        ref m_StateCode,
        ServerStateConst.Starting,
        ServerStateConst.NotStarted);

    if (origStateCode != ServerStateConst.NotStarted)
    {
        // not initialized or already running
        return false;
    }

    s_ActiveConnectionsCounter ??=
        s_Meter.CreateUpDownCounter<int>(
            "active-connections",
            "connections",
            "Number of active connections");

    if (!m_SocketServer.Start())
    {
        m_StateCode = ServerStateConst.NotStarted;
        return false;
    }

    StartedTime = DateTime.Now;
    m_StateCode = ServerStateConst.Running;
    OnStarted();
    return true;
}

3.2 AsyncSocketServer.Start()

TCP 구현은 접속 수락 이후 바로 사용할 수 있도록 receive용 SocketAsyncEventArgsProxy 풀과 send용 SocketAsyncEventArgs 풀을 먼저 만듭니다. PreAllocateSAEA가 true면 MaxConnectionNumber만큼 미리 만들고, false면 MinPoolSize에서 시작합니다. 

public override bool Start()
{
    m_ReceiveSAEAPool = new SmartPool<SocketAsyncEventArgsProxy>();
    var receiveCreator = new SAEAProxyCreator();

    if (AppServer.Config.PreAllocateSAEA)
    {
        m_ReceiveSAEAPool.Initialize(
            AppServer.Config.MaxConnectionNumber,
            AppServer.Config.MaxConnectionNumber,
            receiveCreator);
    }
    else
    {
        m_ReceiveSAEAPool.Initialize(
            AppServer.Config.MinPoolSize,
            AppServer.Config.MaxConnectionNumber,
            receiveCreator);
    }

    m_SendSAEAPool = new SmartPool<SocketAsyncEventArgs>();
    var sendCreator = new SAEACreator();

    // send pool도 receive pool과 같은 정책으로 초기화

    if (!base.Start())
        return false;

    IsRunning = true;
    return true;
}

3.3 SocketServerBase.Start()

공통 기반은 SendingQueue 풀을 만들고, ListenerInfo[]를 순회하며 listener를 생성합니다. TCP에서는 TcpSocketServerBase.CreateListener()가 TcpAsyncSocketListener를 반환합니다. 

public virtual bool Start()
{
    IsStopped = false;

    var config = AppServer.Config;
    var sendingQueuePool = new SmartPool<SendingQueue>();
    sendingQueuePool.Initialize(
        Math.Max(config.MaxConnectionNumber / 6, 256),
        Math.Max(config.MaxConnectionNumber * 2, 256),
        new SendingQueueSourceCreator(config.SendingQueueSize));

    SendingQueuePool = sendingQueuePool;

    for (var i = 0; i < ListenerInfos.Length; i++)
    {
        var listener = CreateListener(ListenerInfos[i]);
        listener.Error += OnListenerError;
        listener.Stopped += OnListenerStopped;
        listener.NewClientAccepted += OnNewClientAccepted;

        if (listener.Start(AppServer.Config))
            Listeners.Add(listener);
        else
            return false;
    }

    IsRunning = true;
    return true;
}

4. TcpAsyncSocketListener: listen socket과 AcceptAsync 루프

listener는 TCP 접속의 입구입니다. Start()에서 listen socket을 만들고, Bind(), Listen() 후 AcceptLoopAsync()를 fire-and-forget으로 실행합니다.

Start에서 하는 일

  • 엔드포인트 address family에 맞는 TCP stream socket 생성
  • Bind(this.Info.EndPoint)로 IP/Port 점유
  • Listen(m_ListenBackLog)로 listen 상태 진입
  • CancellationTokenSource 생성
  • AcceptLoopAsync() 시작

AcceptLoopAsync의 특징

  • AcceptAsync(ct)를 사용하므로 Stop에서 취소 가능
  • 정상 stop 관련 예외는 조용히 루프 종료
  • 일반 예외는 OnError() 후 계속 accept 시도
  • 새 socket을 받으면 OnNewClientAccepted(client, null) 호출
public override bool Start(IServerConfig config)
{
    m_ListenSocket = new Socket(
        this.Info.EndPoint.AddressFamily,
        SocketType.Stream,
        ProtocolType.Tcp);

    try
    {
        m_ListenSocket.Bind(this.Info.EndPoint);
        m_ListenSocket.Listen(m_ListenBackLog);

        m_StopCts = new CancellationTokenSource();
        _ = AcceptLoopAsync(m_StopCts.Token);

        return true;
    }
    catch (Exception e)
    {
        OnError(e);
        return false;
    }
}
private async Task AcceptLoopAsync(CancellationToken ct)
{
    try
    {
        while (true)
        {
            Socket client;

            try
            {
                client = await m_ListenSocket!.AcceptAsync(ct);
            }
            catch (OperationCanceledException) { return; }
            catch (ObjectDisposedException) { return; }
            catch (SocketException se) when (IsStopError(se.ErrorCode))
            {
                return;
            }
            catch (Exception e)
            {
                OnError(e);
                if (ct.IsCancellationRequested)
                    return;
                continue;
            }

            OnNewClientAccepted(client, null);
        }
    }
    finally
    {
        OnStopped();
    }
}
OnNewClientAccepted는 listener base class의 이벤트 발행 메서드입니다. 이 이벤트는 SocketServerBase.Start()에서 AsyncSocketServer.OnNewClientAccepted에 연결되어 있습니다.

5. AsyncSocketServer: accepted socket을 세션으로 승격

listener가 새 socket을 넘기면 AsyncSocketServer는 이 socket을 바로 애플리케이션에 노출하지 않습니다. receive/send 비동기 인자를 풀에서 가져오고, AsyncSocketSession을 만들고, 그 위에 AppSession을 붙인 뒤 등록합니다.

1. accept 이벤트

OnNewClientAccepted()는 서버가 이미 stop 중이면 무시하고, 아니면 ProcessNewClient(client)로 넘깁니다.

2. receive SAEA 확보

receive용 SocketAsyncEventArgsProxy를 풀에서 꺼냅니다. 실패하면 최대 연결 수에 도달한 것으로 보고 socket을 닫습니다.

3. send SAEA 확보

send용 SocketAsyncEventArgs를 풀에서 꺼냅니다. 실패하면 이미 꺼낸 receive proxy를 풀에 되돌리고 socket을 닫습니다.

4. SocketSession 생성

new AsyncSocketSession(client, socketEventArgsProxy, sendSAEA, false)로 소켓 엔진 세션을 만듭니다.

5. AppSession 생성

CreateSession(client, socketSession)이 TCP 옵션을 적용한 뒤 AppServer.CreateAppSession(session)을 호출합니다.

6. 등록 후 시작

세션 close 이벤트를 연결하고 AppServer.RegisterSession()이 성공하면 socketSession.Start()를 비동기로 실행합니다.

protected override void OnNewClientAccepted(
    ISocketListener listener,
    Socket client,
    object? state)
{
    if (IsStopped)
        return;

    ProcessNewClient(client);
}
private IAppSession? ProcessNewClient(Socket client)
{
    SocketAsyncEventArgsProxy? socketEventArgsProxy;
    if (!m_ReceiveSAEAPool!.TryGet(out socketEventArgsProxy))
    {
        AppServer.AsyncRun(client.SafeClose);
        AppServer.Logger.Error(
            $"Max connection number {AppServer.Config.MaxConnectionNumber} was reached!");
        return null;
    }

    SocketAsyncEventArgs? sendSAEA;
    if (!m_SendSAEAPool!.TryGet(out sendSAEA))
    {
        socketEventArgsProxy.Reset();
        m_ReceiveSAEAPool.Push(socketEventArgsProxy);
        AppServer.AsyncRun(client.SafeClose);
        return null;
    }

    var socketSession =
        new AsyncSocketSession(client, socketEventArgsProxy, sendSAEA, false);

    var session = CreateSession(client, socketSession);

    if (session == null)
    {
        socketEventArgsProxy.Reset();
        m_ReceiveSAEAPool.Push(socketEventArgsProxy);
        m_SendSAEAPool.Push(sendSAEA);
        AppServer.AsyncRun(client.SafeClose);
        return null;
    }

    socketSession.Closed += SessionClosed;

    if (RegisterSession(session))
    {
        AppServer.AsyncRun(() => socketSession.Start());
    }

    return session;
}

6. TcpSocketServerBase.CreateSession: accepted socket 옵션 적용

AsyncSocketServer.ProcessNewClient() 안에서 호출되는 CreateSession()은 TcpSocketServerBase에 구현되어 있습니다. 여기서는 네트워크 socket 옵션을 먼저 적용하고, 마지막에 AppServer.CreateAppSession(session)으로 애플리케이션 세션 생성을 위임합니다. 

protected IAppSession CreateSession(Socket client, ISocketSession session)
{
    if (m_SendTimeOut > 0)
        client.SendTimeout = m_SendTimeOut;

    if (m_ReceiveBufferSize > 0)
        client.ReceiveBufferSize = m_ReceiveBufferSize;

    if (m_SendBufferSize > 0)
        client.SendBufferSize = m_SendBufferSize;

    if (!Platform.SupportSocketIOControlByCodeEnum)
    {
        client.SetSocketOption(
            SocketOptionLevel.Socket,
            SocketOptionName.KeepAlive,
            m_KeepAliveOptionValues);
    }
    else
    {
#if WINDOWS
        client.IOControl(
            IOControlCode.KeepAliveValues,
            m_KeepAliveOptionValues,
            m_KeepAliveOptionOutValues);
#endif
    }

    client.NoDelay = m_NoDelay;
    client.LingerState = new LingerOption(enable: false, seconds: 0);

    return this.AppServer.CreateAppSession(session);
}
옵션 설정 출처 효과
SendTimeout ServerConfig.SendTimeOut 동기 send 또는 socket 수준 send 작업의 제한 시간에 영향을 줍니다.
ReceiveBufferSize ServerConfig.ReceiveBufferSize 운영체제 socket receive buffer 크기를 조정합니다. 라이브러리의 Pipe segment 크기에도 같은 설정이 사용됩니다.
SendBufferSize ServerConfig.SendBufferSize 운영체제 socket send buffer 크기를 조정합니다.
KeepAlive KeepAliveTime, KeepAliveInterval 장시간 idle 연결 감지를 위한 TCP keep-alive 옵션입니다. 코드에는 플랫폼별 분기가 있습니다.
NoDelay ServerConfig.NoDelay Nagle 알고리즘 사용 여부를 제어합니다. 실시간 작은 패킷에서는 true가 유리할 수 있지만 트래픽 특성에 따라 결정해야 합니다.
LingerState 코드에서 고정 enable:false로 설정되어 close 시 linger를 사용하지 않습니다.

7. AppSession 생성과 초기화

AppServerBase는 IAppServer.CreateAppSession() 명시적 인터페이스 구현으로 connection filter를 적용한 뒤 실제 TAppSession 인스턴스를 만듭니다. 이 단계가 끝나면 socket session과 app session은 서로를 참조합니다.

7.1 connection filter 적용

IAppSession IAppServer.CreateAppSession(ISocketSession socketSession)
{
    if (!ExecuteConnectionFilters(socketSession.RemoteEndPoint))
        return NullAppSession;

    var appSession = CreateAppSession(socketSession);

    appSession.Initialize(this, socketSession);

    return appSession;
}

ExecuteConnectionFilters()는 설정된 IConnectionFilter 목록을 순서대로 호출합니다. 어느 하나라도 false를 반환하면 이 연결은 거부됩니다.

7.2 실제 TAppSession 생성

protected virtual TAppSession CreateAppSession(ISocketSession socketSession)
{
    return new TAppSession();
}

기본 구현은 단순히 new TAppSession()입니다. 세션 생성 시 DI, 사용자 지정 factory, 초기 상태 주입이 필요하면 이 메서드를 override하는 방식이 자연스럽습니다.

7.3 AppSession.Initialize()

public virtual void Initialize(
    IAppServer<TAppSession, TRequestInfo> appServer,
    ISocketSession socketSession)
{
    var castedAppServer =
        (AppServerBase<TAppSession, TRequestInfo>)appServer;

    AppServer = castedAppServer;
    Charset = castedAppServer.TextEncoding;
    SocketSession = socketSession;
    SessionID = socketSession.SessionID;
    m_Connected = true;

    m_ReceiveFilter =
        castedAppServer.ReceiveFilterFactory.CreateFilter(
            appServer,
            this,
            socketSession.RemoteEndPoint);

    var filterInitializer = m_ReceiveFilter as IReceiveFilterInitializer;
    if (filterInitializer != null)
        filterInitializer.Initialize(castedAppServer, this);

    socketSession.Initialize(this);

    OnInit();
}
이 시점에 receive filter가 세션별로 생성됩니다. 즉, 같은 서버라도 각 연결은 독립적인 filter 상태를 가질 수 있습니다. 부분 패킷 누적 상태가 세션 간에 섞이지 않는 이유입니다.

8. 세션 등록과 NewSessionConnected 이벤트

AsyncSocketServer는 AppSession 생성 후 바로 receive를 시작하지 않고 먼저 서버에 세션을 등록합니다. 등록이 성공해야 사용자 입장에서 “연결된 세션”이 됩니다.

8.1 AppServerBase.RegisterSession()

bool IAppServer.RegisterSession(IAppSession session)
{
    var appSession = (session as TAppSession)!;

    if (!RegisterSession(appSession.SessionID, appSession))
        return false;

    appSession.SocketSession.Closed += OnSocketSessionClosed;

    s_ActiveConnectionsCounter?.Add(
        1,
        new KeyValuePair<string, object?>("server", Name));

    OnNewSessionConnected(appSession);
    return true;
}

8.2 AppServer<TSession,TRequestInfo>의 실제 저장소

AppServerBase.RegisterSession()은 virtual hook이고, 실제 세션 저장은 AppServer<TSession,TRequestInfo>의 ConcurrentDictionary<string,TAppSession>에서 이루어집니다. 

private ConcurrentDictionary<string, TAppSession> m_SessionDict =
    new ConcurrentDictionary<string, TAppSession>(
        StringComparer.OrdinalIgnoreCase);

protected override bool RegisterSession(
    string sessionID,
    TAppSession appSession)
{
    if (m_SessionDict.TryAdd(sessionID, appSession))
        return true;

    Logger.Error("The session is refused because the it's ID already exists!");
    return false;
}

8.3 NewSessionConnected는 비동기 Task로 호출

protected virtual void OnNewSessionConnected(TAppSession session)
{
    var handler = m_NewSessionConnected;
    if (handler == null)
        return;

    Task.Run(() => handler(session));
}
NewSessionConnected 이벤트는 Task.Run()으로 호출됩니다. 이벤트 핸들러에서 오래 걸리는 작업을 하면 해당 작업은 별도 task에서 진행되지만, 세션의 receive 시작 자체는 AsyncSocketServer.ProcessNewClient()의 다음 단계에서 별도로 실행됩니다.

9. AsyncSocketSession.Start: 첫 receive 게시

등록이 성공하면 AsyncSocketServer는 AppServer.AsyncRun(() => socketSession.Start())를 호출합니다. AsyncSocketSession.Start()는 첫 receive를 게시하고, PipeReader 소비 루프를 시작하고, 마지막으로 애플리케이션 세션 시작 이벤트를 호출합니다. 

public override void Start()
{
    StartReceive();
    _ = ProcessPipeAsync();   // PipeReader consumer loop - independent Task

    if (!m_IsReset)
        StartSession();
}

9.1 SocketSession.Initialize()

AppSession.Initialize() 내부에서 socketSession.Initialize(this)가 호출됩니다. 이 단계에서 송신 큐 하나를 풀에서 가져오고, receive pipe를 준비합니다. 

public virtual void Initialize(IAppSession appSession)
{
    AppSession = appSession;
    Config = appSession.Config;
    SyncSend = Config.SyncSend;

    if (m_SendingQueuePool == null)
        m_SendingQueuePool =
            ((SocketServerBase)((ISocketServerAccessor)appSession.AppServer)
                .SocketServer!).SendingQueuePool!;

    SendingQueue? queue;
    if (m_SendingQueuePool!.TryGet(out queue))
    {
        m_SendingQueue = queue;
        queue.StartEnqueue();
    }

    var pipeOptions = new PipeOptions(
        minimumSegmentSize: Config.ReceiveBufferSize,
        useSynchronizationContext: false);

    _receivePipe = new Pipe(pipeOptions);
    _pipeWriter  = _receivePipe.Writer;
    _pipeReader  = _receivePipe.Reader;
}

9.2 AsyncSocketSession.Initialize()

public override void Initialize(IAppSession appSession)
{
    base.Initialize(appSession);

    SocketAsyncProxy.Initialize(this);

    if (!SyncSend)
    {
        if (m_SocketEventArgSend == null)
            m_SocketEventArgSend = new SocketAsyncEventArgs();

        m_SocketEventArgSend.Completed += OnSendingCompleted;
    }
}

9.3 StartReceive()

StartReceive()는 PipeWriter에서 메모리를 받아 receive용 SocketAsyncEventArgs의 buffer로 설정합니다. 그 다음 세션이 receive를 시작할 수 있는 상태인지 확인하고 Client.ReceiveAsync(e)를 게시합니다. 

private void StartReceive()
{
    var e = SocketAsyncProxy.SocketEventArgs;

    try
    {
        var memory = _pipeWriter!.GetMemory(Config.ReceiveBufferSize);
        e.SetBuffer(memory);

        if (!OnReceiveStarted())
            return;

        bool willRaiseEvent = Client!.ReceiveAsync(e);
        if (!willRaiseEvent)
            ProcessReceive(e);
    }
    catch (Exception exc)
    {
        LogError(exc);
        OnReceiveTerminated(CloseReason.SocketError);
    }
}

10. 실패 경로와 자원 정리

접속 흐름은 성공 경로보다 실패 경로가 더 중요할 때가 많습니다. 풀에서 객체를 가져온 뒤 다음 단계가 실패하면 반드시 이미 확보한 자원을 되돌려야 합니다.

receive SAEA를 못 가져온 경우

새 연결 수락은 됐지만 receive용 proxy가 없으면 세션을 만들 수 없습니다. socket을 비동기로 닫고 null을 반환합니다.

send SAEA를 못 가져온 경우

이미 꺼낸 receive proxy를 reset 후 pool에 push하고 socket을 닫습니다.

AppSession 생성 실패

connection filter 거부 또는 생성 실패 시 receive proxy와 send SAEA를 둘 다 pool에 반환하고 socket을 닫습니다.

RegisterSession 실패

중복 SessionID 등으로 등록 실패 시 appSession.SocketSession.Close(CloseReason.InternalError)를 호출합니다.

세션 close 후 SAEA 반환

AsyncSocketServer.SessionClosed()는 AsyncSocketSession에서 receive proxy와 send SAEA를 꺼내 서버가 계속 실행 중이면 pool로 돌려보냅니다. 서버가 stop 중이거나 pool이 없으면 dispose합니다. 

void SessionClosed(ISocketSession session, CloseReason reason)
{
    var socketSession = session as IAsyncSocketSessionBase;
    if (socketSession == null)
        return;

    var proxy = socketSession.SocketAsyncProxy;
    proxy.Reset();
    var args = proxy.SocketEventArgs;

    var serverState = AppServer.State;
    var receivePool = this.m_ReceiveSAEAPool;
    var sendPool = this.m_SendSAEAPool;

    if (receivePool == null ||
        sendPool == null ||
        serverState == ServerState.Stopping ||
        serverState == ServerState.NotStarted)
    {
        args.Dispose();
        socketSession.SendSAEA?.Dispose();
        return;
    }

    if (!proxy.IsRecyclable)
    {
        args.Dispose();
        socketSession.SendSAEA?.Dispose();
        return;
    }

    args.SetBuffer(null, 0, 0);
    receivePool.Push(proxy);

    var sendSAEA = socketSession.SendSAEA;
    if (sendSAEA != null)
    {
        sendSAEA.SetBuffer(null, 0, 0);
        sendPool.Push(sendSAEA);
    }
}

11. ActiveConnect도 같은 세션 생성 경로를 사용

AsyncSocketServer는 서버가 수동으로 accept하는 흐름뿐 아니라, 서버 쪽에서 원격 endpoint로 능동 접속하는 IActiveConnector도 구현합니다. 연결 성공 후에는 ProcessNewClient(socket)를 그대로 호출하므로 이후 세션 생성 경로는 동일합니다. 

Task<ActiveConnectResult> IActiveConnector.ActiveConnect(
    EndPoint targetEndPoint,
    EndPoint? localEndPoint)
{
    var taskSource = new TaskCompletionSource<ActiveConnectResult>();
    var socket = new Socket(
        targetEndPoint.AddressFamily,
        SocketType.Stream,
        ProtocolType.Tcp);

    if (localEndPoint != null)
    {
        socket.ExclusiveAddressUse = false;
        socket.SetSocketOption(
            SocketOptionLevel.Socket,
            SocketOptionName.ReuseAddress,
            true);
        socket.Bind(localEndPoint);
    }

    socket.BeginConnect(
        targetEndPoint,
        OnActiveConnectCallback,
        new ActiveConnectState(taskSource, socket));

    return taskSource.Task;
}
private void OnActiveConnectCallback(IAsyncResult result)
{
    var connectState = result.AsyncState as ActiveConnectState;
    if (connectState == null)
        return;

    try
    {
        var socket = connectState.Socket;
        socket.EndConnect(result);

        var session = ProcessNewClient(socket);

        if (session == null)
            connectState.TaskSource.SetException(
                new Exception("Failed to create session for this socket."));
        else
            connectState.TaskSource.SetResult(
                new ActiveConnectResult { Result = true, Session = session });
    }
    catch (Exception e)
    {
        connectState.TaskSource.SetException(e);
    }
}

12. 전체 시퀀스 한 번에 보기

아래 순서를 외우면 TCP 접속 흐름의 파일 이동이 명확해집니다. 핵심은 listener가 socket을 받고, socket server가 socket session과 app session을 조립하고, 등록 성공 후 socket session이 receive를 시작한다는 점입니다.

1. 서버 시작
AppServerBase.Start() -> m_SocketServer.Start()
2. TCP 구현 시작
AsyncSocketServer.Start() -> receive/send SAEA pool 초기화
3. Listener 시작
SocketServerBase.Start() -> CreateListener() -> TcpAsyncSocketListener.Start()
4. Accept 대기
AcceptLoopAsync() -> m_ListenSocket.AcceptAsync(ct)
5. 새 socket 수락
OnNewClientAccepted(client, null) 이벤트 발행
6. 엔진 세션 생성
AsyncSocketServer.ProcessNewClient() -> SAEA 확보 -> new AsyncSocketSession(...)
7. TCP 옵션 적용
TcpSocketServerBase.CreateSession() -> timeout, buffer, keep-alive, no-delay, linger 적용
8. 앱 세션 생성
AppServer.CreateAppSession() -> filter 생성 -> socketSession.Initialize(this)
9. 등록
AppServer.RegisterSession() -> dictionary 저장 -> close event 연결 -> NewSessionConnected
10. receive 시작
socketSession.Start() -> StartReceive() -> ProcessPipeAsync() -> StartSession()

13. 코드를 읽을 때 확인할 체크리스트

흐름 이해 체크

  • SocketServerFactory가 TCP일 때 AsyncSocketServer를 만드는가?
  • SocketServerBase.Start()가 listener 이벤트를 어디에 연결하는가?
  • TcpAsyncSocketListener.AcceptLoopAsync()가 어떤 예외에서 종료되는가?
  • ProcessNewClient()에서 실패 시 어떤 pool 반환이 필요한가?
  • CreateSession()이 socket 옵션 적용 후 AppSession 생성을 위임하는가?
  • AppSession.Initialize()이 receive filter를 세션별로 만드는가?

운영/튜닝 체크

  • MaxConnectionNumber가 SAEA pool 크기와 실제 동시 접속 한계에 맞는가?
  • PreAllocateSAEA를 true로 둘지, 동적 증가로 둘지 결정했는가?
  • ReceiveBufferSize가 프로토콜 패킷 크기와 맞는가?
  • SendBufferSize, NoDelay, KeepAliveTime을 트래픽 특성에 맞췄는가?
  • connection filter에서 차단한 연결이 null session으로 처리될 때 호출 경로가 안전한가?
  • 세션 close 후 SAEA가 pool로 돌아가는 경로를 로그로 관찰할 수 있는가?
TCP 접속 흐름을 수정할 때는 성공 경로만 보지 말고 pool 고갈, connection filter 거부, AppSession 생성 실패, RegisterSession 실패, 서버 stop 중 close 경로를 같이 확인해야 합니다.

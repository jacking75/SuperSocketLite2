Known Caveats

The things that compile fine but only bite under load. Worth a single skim before you build on the library.

1. Thread safety

NewSessionConnected and NewRequestReceived can be called concurrently from different threads. Watch for race conditions when a client sends a packet immediately after connecting.

Setting ServerConfig.SyncSessionConnectedEvent = true makes NewSessionConnected be called synchronously on the accept path, which structurally guarantees the "connected → first request" ordering. In exchange the handler blocks the accept, so it must be kept light. (Default is false = the previous behaviour.)

2. Send buffer lifetime (zero-copy)

Send(byte[], int, int) / Send(ArraySegment<byte>) / Send(IList<ArraySegment<byte>>) / SendAsync(ReadOnlyMemory<byte>) (when array-backed) enqueue the caller's array by reference. If you modify that array before the send completes, wrong data goes out. 
// Dangerous: code that reuses buffer
session.Send(buffer, 0, len);
buffer[0] = 0;          // the send may still be in flight

// Safe: the session copies into a pooled buffer
session.SendCopied(buffer.AsSpan(0, len));
buffer[0] = 0;          // OK

The list itself passed to Send(IList<...>) is copied at enqueue time, so you can reuse it right after the call (only the arrays are shared).

Empty data is handled differently. TrySendCopied / SendCopied enqueue nothing and return success when the data is empty. Send(buffer, 0, 0), by contrast, enqueues a zero-length segment and actually attempts the send — on UDP that means an empty datagram goes out. You only need to check this when moving a protocol in which empty packets are meaningful from Send to SendCopied.

3. Receive filters

The filter receives a ReadOnlySequence<byte> straight from the pipe. If the request is not complete yet, just leave consumed where it is — the data stays in the pipe and arrives contiguously on the next receive. A filter that keeps its own carry buffer only adds copying.

header / body may span several segments. Do not read them via header.First.Span; use CopyTo(Span) or ToArray().

With UDP + UdpRequestInfo, the filter used to parse the sessionID is reused, one per receive thread (reused after Reset()). It must not carry state between datagrams, and must not capture the remote endpoint passed to CreateFilter.

4. Lifetime of RequestInfo and its body

The library calls the NewRequestReceived handler synchronously, and only advances the pipe after every handler has returned (AppServerBase.ExecuteCommand → AdvanceTo in ProcessPipeAsync). UDP is the same — UdpReceivePacket.Dispose() returns the receive buffer to the pool after the handler returns.

This guarantee is what lets an app get to zero allocations per packet: the filter reuses a single request instance and passes the body straight through as a ReadOnlySequence<byte>. Tutorials/EchoServer has that shape.

In exchange there is a contract:

  • Once the handler returns, that RequestInfo and its body are no longer valid. Do not store them in a field, capture them in a lambda, or put them on another thread's queue.
  • To keep a value, deserialize or copy it inside the handler.
  • If your structure hands packets off to a logic thread, you cannot use this approach. Borrow from ArrayPool, copy, and return in one place after processing — Tutorials/PvPGameServer has that shape.
Breaking this still compiles, and usually works under light load. Data only corrupts once load is high enough for the pipe buffer to be recycled, which makes it hard to find. For the details see Docs/GC_Copy_Minimization.md (Korean).

5. Time values are UTC

AppSession.StartTime / LastActiveTime and AppServerBase.StartedTime are UTC. Append .ToLocalTime() to print local time in a UI or log. LastActiveTime is derived back from a monotonic tick, so it carries a few milliseconds of error.

6. Timeout handling order

When closing a session after a TimeoutException, always follow this order.

// correct order
session.SendEndWhenSendingTimeOut();
session.Close();

// Calling Close() alone, without SendEndWhenSendingTimeOut(), leaves the socket uncleaned.

7. Exceeding the maximum connection count

When MaxConnectionNumber is exceeded, SuperSocketLite drops the connection immediately. In that case NewSessionConnected is not called.

8. UDP mode

A UDP session's _client(Socket) may be null (the socket instance is shared). Close() branches internally between the UDP and TCP paths, so take care when modifying UDP-related code.

송신 파이프라인과 ChannelSendingQueue

송신은 AppSession.Send()에서 시작해 SocketSession.TrySend(), 세션별 ChannelSendingQueue, 실제 socket send, 완료 콜백으로 이어집니다. 이전 이중 SendingQueue swap 모델은 현재 활성 경로가 아닙니다.

1. 전체 흐름

AppSession.Send(data)
  -> SocketSession.TrySend(segment or segments)
  -> ChannelSendingQueue.TryEnqueue(...)
  -> StartSend(initial: true)
  -> ChannelSendingQueue.DrainAvailable()
  -> SendAsync(items) or SendSync(items)
  -> OnSendingCompleted(items)
  -> pending item이 있으면 StartSend(initial: false)

세션에서는 동시에 하나의 실제 send만 진행합니다. 이 제어는 SocketState.InSending flag가 담당하고, enqueue 자체는 bounded Channel<ArraySegment<byte>>가 담당합니다.

2. AppSession Send API

애플리케이션은 AppSession.Send() 또는 TrySend()를 호출합니다. collect-send가 꺼져 있으면 즉시 SocketSession.TrySend()로 내려갑니다. collect-send가 켜져 있으면 먼저 ReuseLockBaseBuffer에 복사하고, 주기 timer가 snapshot을 만들어 보냅니다.

3. ChannelSendingQueue

ChannelSendingQueue는 내부적으로 bounded channel을 사용합니다. FullMode는 Wait지만 공개 enqueue API는 TryWrite 기반이므로 capacity를 넘으면 대기하지 않고 false를 반환합니다. 

internal sealed class ChannelSendingQueue
{
    private readonly Channel<ArraySegment<byte>> m_Channel;
    private readonly object m_SyncRoot = new object();
    private readonly int m_Capacity;
    private int m_Count;
    private bool m_Completed;

    public bool TryEnqueue(ArraySegment<byte> item);
    public bool TryEnqueue(IList<ArraySegment<byte>> items);
    public IList<ArraySegment<byte>> DrainAvailable();
    public void Complete();
}
메서드역할
TryEnqueue(ArraySegment<byte>)단일 segment를 capacity 안에서 channel에 기록합니다.
TryEnqueue(IList<ArraySegment<byte>>)여러 segment를 하나의 논리 send로 capacity 검사 후 기록합니다.
DrainAvailable()현재 channel에 쌓인 segment를 한 번에 읽어 socket send batch로 만듭니다.
Complete()close 시 writer를 완료하고 이후 enqueue를 차단합니다.

TryEnqueue(IList<ArraySegment<byte>>)와 Complete()는 같은 lock과 m_Completed flag를 사용합니다. 따라서 close와 batch enqueue가 경합해도 일부 segment만 publish되는 상태를 만들지 않습니다.

4. SocketSession.TrySend()

public bool TrySend(ArraySegment<byte> segment)
{
    if (IsClosed)
        return false;

    if (!m_SendQueue.TryEnqueue(segment))
        return false;

    StartSend(true);
    return true;
}

list overload도 같은 방식입니다. enqueue가 성공하면 StartSend(true)를 호출합니다. 이미 다른 send가 진행 중이면 SocketState.InSending 획득이 실패하고 조용히 반환합니다. 이때 데이터는 channel에 남아 있다가 진행 중인 send 완료 콜백에서 drain됩니다.

5. StartSend와 drain

private void StartSend(bool initial)
{
    if (initial && !TryAddStateFlag(SocketState.InSending))
        return;

    if (IsInClosingOrClosed && TryValidateClosedBySocket(out _))
    {
        OnSendEnd();
        return;
    }

    var items = m_SendQueue.DrainAvailable();
    if (items.Count == 0)
    {
        OnSendEnd();
        return;
    }

    Send(items);
}

현재 시점에 channel에 있는 모든 segment를 DrainAvailable()로 가져와 하나의 batch로 보냅니다.

6. AsyncSocketSession.SendAsync()

비동기 TCP 송신은 send용 SocketAsyncEventArgs에 segment list를 설정하고 Socket.SendAsync()를 호출합니다. 완료가 동기적으로 발생하면 completion handler를 직접 호출합니다. 

protected override void SendAsync(IList<ArraySegment<byte>> items)
{
    var sae = m_SocketEventArgSend;
    sae.BufferList = items;
    sae.UserToken = items;

    if (!client.SendAsync(sae))
        sending_Completed(client, sae);
}

완료 콜백에서 실제 전송 byte 수가 batch 전체보다 작으면 남은 segment를 계산해 다시 보냅니다. 전체가 끝나면 OnSendingCompleted(sentItems)를 호출합니다.

7. Sync send

SyncSend 또는 collect-send 모드에서는 동기 socket send 경로를 사용합니다. 동기 경로도 partial send를 고려해 모든 segment가 전송될 때까지 offset을 갱신하며 반복합니다.

8. 완료 콜백

protected virtual void OnSendingCompleted(IList<ArraySegment<byte>> sentItems)
{
    if (IsInClosingOrClosed)
    {
        if (m_SendQueue.Count > 0 && !TryValidateClosedBySocket(out _))
            StartSend(false);
        else
            OnSendEnd();
        return;
    }

    if (m_SendQueue.Count > 0)
        StartSend(false);
    else
        OnSendEnd();
}

channel에 남은 데이터가 있으면 다음 batch를 보내고, 없으면 InSending flag를 제거합니다.

9. Collect Send

CollectSendIntervalMillSec > 0이면 AppSession.Send()가 즉시 socket send를 시작하지 않고 세션의 ReuseLockBaseBuffer에 데이터를 모읍니다. AppServer.CollectSendSession() timer가 session buffer를 snapshot byte[]로 복사해 session.Send(snapshot)을 호출합니다.

snapshot을 만든 뒤 CommitCollectSend(sendDataLength)를 호출하므로 send 중 원본 collect buffer가 변경되어도 보낼 데이터가 훼손되지 않습니다. AppServer.Stop()은 collect-send timer를 중지하고 dispose합니다.

10. UDP 송신

UdpSocketSession도 IList<ArraySegment<byte>> batch를 받습니다. 실제 전송은 listener socket의 SendToAsync() 또는 동기 SendTo()를 사용하며, 대상은 세션의 RemoteEndPoint입니다.

11. Legacy SendingQueue

SuperSocketLite.Common.SendingQueue 타입은 아직 테스트와 호환성 목적으로 남아 있습니다. 하지만 현재 SocketSession은 ChannelSendingQueue를 사용하고, SocketServerBase는 SendingQueue pool을 만들지 않습니다. 새 동작을 분석할 때는 Common/ChannelSendingQueue.cs, SocketSession.cs, AsyncSocketSession.cs, UdpSocketSession.cs를 기준으로 보십시오.

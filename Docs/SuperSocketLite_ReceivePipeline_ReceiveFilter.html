SuperSocketLite 수신 파이프라인과 ReceiveFilter 상세 분석

이 문서는 기존 SuperSocketLite_Architecture.html의 “6. 수신 파이프라인”과 “7. ReceiveFilter와 요청 처리”를 하나로 묶어 확장한 문서입니다. TCP socket에서 받은 바이트가 SocketAsyncEventArgs, PipeWriter, PipeReader, AppSession.ProcessRequest, IReceiveFilter, AppServer.ExecuteCommand를 거쳐 사용자 핸들러까지 도달하는 과정을 코드 중심으로 설명합니다.

1. 전체 지도

수신 경로는 생산자와 소비자로 나뉩니다. 생산자는 socket receive 완료 시 받은 바이트를 PipeWriter에 밀어 넣고, 소비자는 PipeReader에서 읽은 바이트를 AppSession과 IReceiveFilter로 전달합니다.

이 문서는 Windows 전용 완료 모델 이름을 일반 설명에 사용하지 않고, 크로스플랫폼 .NET API 관점에서 SocketAsyncEventArgs, ReceiveAsync, System.IO.Pipelines 중심으로 설명합니다.

2. 핵심 객체와 책임

객체 주요 파일 수신 경로에서 하는 일
AsyncSocketSession AsyncSocketSession.cs receive용 SocketAsyncEventArgs에 PipeWriter memory를 연결하고, ReceiveAsync 완료 후 받은 바이트 수만큼 PipeWriter를 전진시킵니다.
SocketSession SocketSession.cs 세션 상태 플래그, receive pipe, ProcessPipeAsync() 소비 루프, close 처리의 공통 기반입니다.
AppSession SocketBase/AppSession.cs 세션별 IReceiveFilter와 carry buffer를 들고, bytes를 requestInfo로 바꾼 뒤 AppServer로 실행을 넘깁니다.
AppServerBase SocketBase/AppServerBase.cs RawDataReceived hook, NewRequestReceived 이벤트, command 실행, metrics 증가를 담당합니다.
IReceiveFilter SocketBase/Protocol/IReceiveFilter.cs 바이트 조각을 누적/분석해 완전한 TRequestInfo를 반환합니다. 부족하면 null을 반환합니다.
FixedSizeReceiveFilter Protocol/FixedSizeReceiveFilter.cs 고정 길이 단위로 패킷을 자르고, 부분 수신 상태를 m_ParsedLength와 OffsetDelta로 보존합니다.
FixedHeaderReceiveFilter Protocol/FixedHeaderReceiveFilter.cs 고정 길이 헤더를 먼저 읽고, 헤더에서 바디 길이를 계산한 뒤 바디까지 모아 requestInfo를 만듭니다.

3. 초기화: 세션마다 Pipe와 ReceiveFilter가 만들어진다

수신 파이프라인은 세션 생성 시점에 준비됩니다. AppSession.Initialize()는 세션별 receive filter를 만들고, SocketSession.Initialize()는 PipeWriter/PipeReader를 준비합니다.

3.1 AppSession.Initialize(): 세션별 filter 생성

public virtual void Initialize(
    IAppServer<TAppSession, TRequestInfo> appServer,
    ISocketSession socketSession)
{
    var castedAppServer =
        (AppServerBase<TAppSession, TRequestInfo>)appServer;

    AppServer = castedAppServer;
    Charset = castedAppServer.TextEncoding;
    SocketSession = socketSession;
    SessionID = socketSession.SessionID;
    m_Connected = true;

    m_ReceiveFilter =
        castedAppServer.ReceiveFilterFactory.CreateFilter(
            appServer,
            this,
            socketSession.RemoteEndPoint);

    var filterInitializer = m_ReceiveFilter as IReceiveFilterInitializer;
    if (filterInitializer != null)
        filterInitializer.Initialize(castedAppServer, this);

    socketSession.Initialize(this);

    OnInit();
}
중요한 점은 CreateFilter()가 세션마다 호출된다는 것입니다. 필터 내부에 부분 패킷 상태가 있어도 다른 세션과 섞이지 않습니다.

3.2 SocketSession.Initialize(): Pipe 준비

public virtual void Initialize(IAppSession appSession)
{
    AppSession = appSession;
    Config = appSession.Config;
    SyncSend = Config.SyncSend;

    // SendingQueue 초기화 생략

    var pipeOptions = new PipeOptions(
        minimumSegmentSize: Config.ReceiveBufferSize,
        useSynchronizationContext: false);

    _receivePipe = new Pipe(pipeOptions);
    _pipeWriter  = _receivePipe.Writer;
    _pipeReader  = _receivePipe.Reader;
}

minimumSegmentSize에는 ReceiveBufferSize가 들어갑니다. receive buffer 크기가 커지면 한 번에 받을 수 있는 메모리 세그먼트 크기도 같이 영향을 받습니다.

4. 수신 생산자: AsyncSocketSession이 PipeWriter에 쓴다

생산자 역할은 AsyncSocketSession이 맡습니다. 핵심은 receive 완료 콜백에서 직접 AppSession.ProcessRequest()를 호출하지 않고, PipeWriter에 바이트를 쓰고 다음 receive를 예약한다는 점입니다.

4.1 Start(): receive와 pipe 소비 루프를 둘 다 시작

public override void Start()
{
    StartReceive();
    _ = ProcessPipeAsync();   // PipeReader consumer loop - independent Task

    if (!m_IsReset)
        StartSession();
}

StartReceive()는 socket에서 bytes를 읽는 생산자 쪽 시작점이고, ProcessPipeAsync()는 PipeReader에서 bytes를 읽어 request로 해석하는 소비자 쪽 시작점입니다.

4.2 StartReceive(): PipeWriter memory를 SocketAsyncEventArgs에 연결

private void StartReceive()
{
    var e = SocketAsyncProxy.SocketEventArgs;

    try
    {
        var memory = _pipeWriter!.GetMemory(Config.ReceiveBufferSize);
        e.SetBuffer(memory);   // .NET 5+ Memory<byte> overload

        if (!OnReceiveStarted())
            return;

        bool willRaiseEvent = Client!.ReceiveAsync(e);
        if (!willRaiseEvent)
            ProcessReceive(e);
    }
    catch (Exception exc)
    {
        LogError(exc);
        OnReceiveTerminated(CloseReason.SocketError);
    }
}
GetMemory(): PipeWriter가 관리하는 쓰기 가능한 메모리 영역을 얻습니다.
e.SetBuffer(memory): receive 결과가 PipeWriter memory에 직접 들어가도록 설정합니다.
OnReceiveStarted(): 세션이 closing 상태가 아닌지 확인하고 InReceiving 플래그를 세웁니다.
ReceiveAsync(): true면 나중에 완료 이벤트가 오고, false면 이미 완료된 것이므로 바로 ProcessReceive()를 호출합니다.

4.3 ProcessReceive(): PipeWriter.Advance와 Flush

public void ProcessReceive(SocketAsyncEventArgs e)
{
    if (!ProcessCompleted(e))
    {
        _pipeWriter!.Complete();
        OnReceiveTerminated(e.SocketError == SocketError.Success
            ? CloseReason.ClientClosing
            : CloseReason.SocketError);
        return;
    }

    OnReceiveEnded();

    AppSession?.AppServer.RecordBytesReceived(e.BytesTransferred);

    _pipeWriter!.Advance(e.BytesTransferred);
    var flushTask = _pipeWriter.FlushAsync();

    if (flushTask.IsCompleted)
    {
        StartReceive();
    }
    else
    {
        _ = flushTask.AsTask().ContinueWith(
            _ => StartReceive(),
            TaskContinuationOptions.ExecuteSynchronously);
    }
}
ProcessReceive()는 받은 데이터를 해석하지 않습니다. 바이트 수만큼 Advance()하고 FlushAsync()로 PipeReader 쪽에 알린 뒤, backpressure 상태에 따라 다음 receive를 즉시 또는 flush 완료 후 다시 시작합니다.

5. Pipe 소비자: SocketSession.ProcessPipeAsync

소비 루프는 SocketSession에 있습니다. PipeReader에서 읽은 ReadOnlySequence<byte>를 AppSession.ProcessRequest(sequence)에 넘기고, 처리 후 AdvanceTo()로 PipeReader에게 소비 지점을 알려줍니다. 

protected async Task ProcessPipeAsync()
{
    while (true)
    {
        ReadResult result;

        try
        {
            result = await _pipeReader!.ReadAsync();
        }
        catch
        {
            break;
        }

        var buffer = result.Buffer;

        if (buffer.IsEmpty && (result.IsCompleted || result.IsCanceled))
            break;

        SequencePosition consumed = buffer.Start;

        try
        {
            consumed = AppSession.ProcessRequest(buffer);
        }
        catch (Exception exc)
        {
            LogError("Protocol error", exc);
            Close(CloseReason.ProtocolError);
            break;
        }
        finally
        {
            _pipeReader.AdvanceTo(consumed, buffer.End);
        }

        if (result.IsCompleted || result.IsCanceled)
            break;
    }

    _pipeReader!.Complete();
    AppSession?.CompleteReceivePipe();
}

ReadAsync()

생산자가 flush한 바이트를 읽습니다. 결과는 하나의 연속 배열이 아니라 여러 segment일 수 있는 ReadOnlySequence입니다.

ProcessRequest()

기존 IReceiveFilter 구현은 byte[] 기반이므로 AppSession에서 carry buffer로 연결합니다.

AdvanceTo()

이 구현에서는 partial packet 상태를 AppSession/filter에 보존하므로 consumed와 examined를 끝으로 넘겨 PipeReader 메모리를 회수할 수 있게 합니다.

6. AppSession의 carry buffer: Pipe와 기존 필터의 연결부

기존 receive filter들은 byte[] readBuffer, int offset, int length 형태로 설계되어 있습니다. 하지만 PipeReader는 ReadOnlySequence<byte>를 줍니다. 이 둘을 연결하기 위해 AppSession은 세션별 _filterBuffer를 사용합니다.

6.1 ProcessRequest(ReadOnlySequence<byte>)

SequencePosition IAppSession.ProcessRequest(ReadOnlySequence<byte> sequence)
{
    var filterOffsetAdapter = m_ReceiveFilter as IOffsetAdapter;
    int writeOffset = filterOffsetAdapter?.OffsetDelta ?? 0;

    int newLength = (int)sequence.Length;
    int neededSize = writeOffset + newLength;

    if (_filterBuffer == null || _filterBuffer.Length < neededSize)
    {
        int newSize = Math.Max(Config.ReceiveBufferSize * 2, neededSize);
        var newBuf = ArrayPool<byte>.Shared.Rent(newSize);

        if (_filterBuffer != null)
        {
            if (writeOffset > 0)
                Array.Copy(_filterBuffer, 0, newBuf, 0, writeOffset);
            ArrayPool<byte>.Shared.Return(_filterBuffer);
        }

        _filterBuffer = newBuf;
    }

    sequence.CopyTo(new Span<byte>(_filterBuffer, writeOffset, newLength));

    int offset = writeOffset;
    int length = newLength;

    while (true)
    {
        var requestInfo =
            FilterRequest(_filterBuffer, offset, length, false, out int rest, out _);

        if (requestInfo != null)
        {
            AppServer.ExecuteCommand(this, requestInfo);
        }

        if (rest <= 0)
            break;

        offset = offset + length - rest;
        length = rest;
    }

    return sequence.End;
}

6.2 writeOffset의 의미

FixedSizeReceiveFilter 같은 필터는 부분 패킷을 받으면 OffsetDelta에 이미 누적한 바이트 수를 보관합니다. 다음 PipeReader sequence가 오면 AppSession은 새 bytes를 _filterBuffer[OffsetDelta] 위치부터 복사합니다.

6.3 CompleteReceivePipe(): ArrayPool 반환

public void CompleteReceivePipe()
{
    var buf = _filterBuffer;
    if (buf != null)
    {
        _filterBuffer = null;
        ArrayPool<byte>.Shared.Return(buf);
    }
}

SocketSession.ProcessPipeAsync() 루프가 완전히 끝난 뒤에 호출됩니다. 이 순서가 중요한 이유는 filter 처리 중인 buffer를 먼저 pool에 반환하면 이후 접근이 위험하기 때문입니다.

7. FilterRequest: raw bytes에서 requestInfo로 가는 관문

FilterRequest()는 실제 필터 호출 전후의 정책을 담당합니다. raw data hook, protocol error, offset delta, 최대 요청 길이, 다음 필터 전환을 모두 여기에서 처리합니다. 

TRequestInfo? FilterRequest(
    byte[] readBuffer,
    int offset,
    int length,
    bool toBeCopied,
    out int rest,
    out int offsetDelta)
{
    if (!AppServer.OnRawDataReceived(this, readBuffer, offset, length))
    {
        rest = 0;
        offsetDelta = 0;
        return null;
    }

    var currentRequestLength = m_ReceiveFilter.LeftBufferSize;

    var requestInfo =
        m_ReceiveFilter.Filter(readBuffer, offset, length, toBeCopied, out rest);

    if (m_ReceiveFilter.State == FilterState.Error)
    {
        rest = 0;
        offsetDelta = 0;
        Close(CloseReason.ProtocolError);
        return null;
    }

    var offsetAdapter = m_ReceiveFilter as IOffsetAdapter;
    offsetDelta = offsetAdapter != null ? offsetAdapter.OffsetDelta : 0;

    if (requestInfo == null)
        currentRequestLength = m_ReceiveFilter.LeftBufferSize;
    else
        currentRequestLength = currentRequestLength + length - rest;

    var maxRequestLength = GetMaxRequestLength();

    if (currentRequestLength >= maxRequestLength)
    {
        Logger.Error($"Max request length: {maxRequestLength}, " +
                     $"current processed length: {currentRequestLength}");
        Close(CloseReason.ProtocolError);
        return null;
    }

    if (m_ReceiveFilter.NextReceiveFilter != null)
        m_ReceiveFilter = m_ReceiveFilter.NextReceiveFilter;

    return requestInfo;
}
코드 지점 역할 이해 포인트
OnRawDataReceived 필터 전 raw byte hook false를 반환하면 해당 수신 데이터는 더 처리하지 않습니다.
m_ReceiveFilter.Filter(...) 프로토콜 파싱 본체 완전한 요청이면 requestInfo, 부족하면 null을 반환합니다.
FilterState.Error 프로토콜 오류 감지 세션은 ProtocolError로 닫힙니다.
IOffsetAdapter.OffsetDelta 다음 bytes를 붙일 위치 Pipe 경로에서는 carry buffer의 write offset이 됩니다.
MaxRequestLength 요청 길이 제한 부분 패킷 누적 공격이나 잘못된 길이 헤더를 차단하는 안전장치입니다.
NextReceiveFilter 필터 전환 프로토콜 단계가 바뀌는 경우 다음 receive부터 다른 필터를 사용할 수 있습니다.

8. ProcessRequest 루프: 한 번의 receive에 여러 요청이 들어올 수 있다

TCP는 stream입니다. 한 번의 receive가 요청 하나와 일치한다는 보장이 없습니다. 한 receive 안에 요청이 여러 개 들어올 수도 있고, 요청 하나가 여러 receive로 나뉠 수도 있습니다. 이 문제를 rest와 while loop가 처리합니다.

8.1 byte[] 기반 루프

int IAppSession.ProcessRequest(
    byte[] readBuffer,
    int offset,
    int length,
    bool toBeCopied)
{
    int rest, offsetDelta;

    while (true)
    {
        var requestInfo =
            FilterRequest(readBuffer, offset, length, toBeCopied,
                          out rest, out offsetDelta);

        if (requestInfo != null)
        {
            try
            {
                AppServer.ExecuteCommand(this, requestInfo);
            }
            catch (Exception e)
            {
                HandleException(e);
            }
        }

        if (rest <= 0)
        {
            return offsetDelta;
        }

        offset = offset + length - rest;
        length = rest;
    }
}

8.2 rest 계산 예시

예를 들어 필터가 5바이트 헤더와 3바이트 바디로 이루어진 8바이트 패킷을 만들었고, receive buffer에는 12바이트가 들어왔다고 가정합니다. 필터는 첫 8바이트로 requestInfo를 만들고 rest = 4를 반환합니다. 그러면 루프는 offset을 다음 요청의 시작 위치로 이동시켜 남은 4바이트를 다시 필터에 넣습니다.

H1 H2 H3 H4 H5 B1 B2 B3 N1 N2 N3 N4
offset = offset + length - rest는 “이번에 소비한 바이트 수만큼 offset을 전진”한다는 뜻입니다.

9. ExecuteCommand: RequestInfo가 사용자 핸들러로 도착하는 곳

필터가 TRequestInfo를 반환하면 AppSession은 AppServer.ExecuteCommand(this, requestInfo)를 호출합니다. 실제 사용자 이벤트는 AppServerBase.NewRequestReceived입니다. 

public virtual event RequestHandler<TAppSession, TRequestInfo>
    NewRequestReceived
{
    add { m_RequestHandler += value; }
    remove { m_RequestHandler -= value; }
}
protected virtual void ExecuteCommand(
    TAppSession session,
    TRequestInfo requestInfo)
{
    session.CurrentCommand = requestInfo.Key;

    var handler = m_RequestHandler;
    if (handler == null)
        return;

    try
    {
        handler(session, requestInfo);
    }
    catch (Exception e)
    {
        session.InternalHandleExcetion(e);
    }

    session.PrevCommand = requestInfo.Key;
    session.LastActiveTime = DateTime.Now;

    Interlocked.Increment(ref m_TotalHandledRequests);
    s_TotalRequestsCounter.Add(1, new KeyValuePair<string, object?>("server", Name));
}

CurrentCommand

현재 처리 중인 request key를 세션에 기록합니다.

handler(session, requestInfo)

사용자가 등록한 NewRequestReceived 핸들러가 여기서 호출됩니다.

metrics

요청 처리 수와 total requests counter가 증가합니다.

10. IReceiveFilter 계약

ReceiveFilter는 “바이트를 넣으면 완성된 요청이 나올 수도 있고, 아직 부족하면 null이 나오는 상태 객체”입니다. TCP stream 파싱의 핵심 상태가 필터 안에 있습니다. 

public interface IReceiveFilter<TRequestInfo>
    where TRequestInfo : IRequestInfo
{
    TRequestInfo? Filter(
        byte[] readBuffer,
        int offset,
        int length,
        bool toBeCopied,
        out int rest);

    TRequestInfo? Filter(
        ReadOnlySpan<byte> buffer,
        bool toBeCopied,
        out int rest)
    {
        byte[] tempBuffer = buffer.ToArray();
        return Filter(tempBuffer, 0, tempBuffer.Length, toBeCopied, out rest);
    }

    int LeftBufferSize { get; }

    IReceiveFilter<TRequestInfo>? NextReceiveFilter { get; }

    void Reset();

    FilterState State { get; }
}
멤버 의미 구현 시 주의점
Filter(...) 바이트 조각을 처리하고 요청을 반환합니다. 완전한 요청이 없으면 null을 반환하고 내부 상태를 유지해야 합니다.
rest 현재 buffer 안에 아직 처리하지 않은 남은 바이트 수입니다. 한 receive에 여러 요청이 섞인 경우 정확한 rest 계산이 중요합니다.
LeftBufferSize 필터 내부에 누적된 부분 데이터 길이입니다. MaxRequestLength 검증에 사용됩니다.
NextReceiveFilter 다음 수신부터 사용할 필터입니다. 로그인 전/후, 핸드셰이크 후 프로토콜 전환 같은 상황에 쓸 수 있습니다.
State 필터 상태입니다. FilterState.Error면 세션이 프로토콜 오류로 종료됩니다.

11. ReceiveFilterBase: segment 누적 기반 필터의 공통 기반

ReceiveFilterBase는 여러 조각으로 나뉜 데이터를 ArraySegmentList에 누적하는 편의 기능을 제공합니다. 직접 필터를 만들 때 이 기반을 사용하면 조각난 데이터를 모으기 쉽습니다. 

public abstract class ReceiveFilterBase<TRequestInfo>
    : IReceiveFilter<TRequestInfo>
    where TRequestInfo : IRequestInfo
{
    private ArraySegmentList m_BufferSegments = null!;

    protected ArraySegmentList BufferSegments
    {
        get { return m_BufferSegments; }
    }

    protected ReceiveFilterBase()
    {
        m_BufferSegments = new ArraySegmentList();
    }

    public abstract TRequestInfo? Filter(
        byte[] readBuffer,
        int offset,
        int length,
        bool toBeCopied,
        out int rest);

    public int LeftBufferSize
    {
        get { return m_BufferSegments.Count; }
    }

    public IReceiveFilter<TRequestInfo>? NextReceiveFilter { get; protected set; }

    protected void AddArraySegment(
        byte[] buffer,
        int offset,
        int length,
        bool toBeCopied)
    {
        m_BufferSegments.AddSegment(buffer, offset, length, toBeCopied);
    }

    protected void ClearBufferSegments()
    {
        m_BufferSegments.ClearSegements();
    }

    public virtual void Reset()
    {
        if (m_BufferSegments != null && m_BufferSegments.Count > 0)
            m_BufferSegments.ClearSegements();
    }

    public FilterState State { get; protected set; }
}
반면 FixedSizeReceiveFilter는 ReceiveFilterBase를 상속하지 않고 직접 IReceiveFilter, IOffsetAdapter, IReceiveFilterInitializer를 구현합니다. 고정 크기 파싱에 특화되어 있기 때문입니다.

12. FixedSizeReceiveFilter: 고정 길이 수신의 기본 원리

FixedSizeReceiveFilter는 “정해진 크기만큼 모이면 요청 하나를 만든다”는 단순한 모델입니다. 이 클래스는 FixedHeaderReceiveFilter의 기반이기도 합니다.

12.1 핵심 필드

public abstract class FixedSizeReceiveFilter<TRequestInfo>
    : IReceiveFilter<TRequestInfo>,
      IOffsetAdapter,
      IReceiveFilterInitializer
    where TRequestInfo : IRequestInfo
{
    private int m_ParsedLength;
    private int m_Size;
    private int m_OrigOffset;
    private int m_OffsetDelta;

    public int Size
    {
        get { return m_Size; }
    }

    public int LeftBufferSize
    {
        get { return m_ParsedLength; }
    }

    int IOffsetAdapter.OffsetDelta
    {
        get { return m_OffsetDelta; }
    }
}

m_ParsedLength

아직 완성되지 않은 현재 요청에서 이미 받은 바이트 수입니다.

m_OffsetDelta

다음 receive bytes를 carry buffer 어디에 붙일지 알려주는 값입니다.

12.2 Filter(byte[]) 로직

public virtual TRequestInfo? Filter(
    byte[] readBuffer,
    int offset,
    int length,
    bool toBeCopied,
    out int rest)
{
    rest = m_ParsedLength + length - m_Size;

    if (rest >= 0)
    {
        var requestInfo =
            ProcessMatchedRequest(
                readBuffer,
                offset - m_ParsedLength,
                m_Size,
                toBeCopied);
        InternalReset();
        return requestInfo;
    }
    else
    {
        m_ParsedLength += length;
        m_OffsetDelta = m_ParsedLength;
        rest = 0;

        var expectedOffset = offset + length;
        var newOffset = m_OrigOffset + m_OffsetDelta;

        if (newOffset < expectedOffset)
        {
            Buffer.BlockCopy(
                readBuffer,
                offset - m_ParsedLength + length,
                readBuffer,
                m_OrigOffset,
                m_ParsedLength);
        }

        return NullRequestInfo;
    }
}

12.3 rest 공식 이해

rest = m_ParsedLength + length - m_Size입니다. 이미 받은 바이트와 이번에 받은 바이트를 합쳐 필요한 크기보다 크거나 같으면 요청 하나를 만들 수 있습니다.

상황 예 결과
아직 부족 m_ParsedLength=0, length=3, m_Size=5 -> rest=-2 m_ParsedLength=3, OffsetDelta=3, requestInfo 없음
정확히 완성 m_ParsedLength=3, length=2, m_Size=5 -> rest=0 ProcessMatchedRequest() 호출, 상태 reset
완성 후 남음 m_ParsedLength=0, length=8, m_Size=5 -> rest=3 첫 5바이트로 requestInfo 생성, 남은 3바이트는 AppSession 루프가 다시 처리

12.4 ProcessMatchedRequest는 사용자 구현 지점

protected abstract TRequestInfo? ProcessMatchedRequest(
    byte[] buffer,
    int offset,
    int length,
    bool toBeCopied);

고정 크기만큼 모였을 때 실제 TRequestInfo를 만드는 메서드입니다. FixedHeaderReceiveFilter는 이 메서드를 override해 “헤더를 찾았다”는 상태로 전환합니다.

13. FixedHeaderReceiveFilter: 헤더+바디 프로토콜 상태 머신

게임 서버에서 흔한 패킷 구조는 [고정 크기 헤더][가변 길이 바디]입니다. FixedHeaderReceiveFilter는 먼저 FixedSizeReceiveFilter로 헤더 크기만큼 읽고, 헤더에서 바디 길이를 계산한 다음 바디를 모아 requestInfo를 만듭니다.

13.1 상태 필드

public abstract class FixedHeaderReceiveFilter<TRequestInfo>
    : FixedSizeReceiveFilter<TRequestInfo>
    where TRequestInfo : IRequestInfo
{
    private bool m_FoundHeader = false;
    private ArraySegment<byte> m_Header;
    private int m_BodyLength;
    private ArraySegmentList m_BodyBuffer = null!;

    protected FixedHeaderReceiveFilter(int headerSize)
        : base(headerSize)
    {
    }
}

13.2 헤더를 읽은 순간: ProcessMatchedRequest

protected override TRequestInfo? ProcessMatchedRequest(
    byte[] buffer,
    int offset,
    int length,
    bool toBeCopied)
{
    m_FoundHeader = true;

    m_BodyLength = GetBodyLengthFromHeader(buffer, offset, Size);

    if (toBeCopied)
        m_Header = new ArraySegment<byte>(buffer.CloneRange(offset, Size));
    else
        m_Header = new ArraySegment<byte>(buffer, offset, Size);

    if (m_BodyLength > 0)
        return NullRequestInfo;

    m_FoundHeader = false;
    return ResolveRequestInfo(m_Header, null, 0, 0);
}

헤더가 완성되면 바로 requestInfo를 만들지 않습니다. 먼저 GetBodyLengthFromHeader()로 바디 길이를 계산합니다. 바디 길이가 0보다 크면 m_FoundHeader=true 상태로 남아 다음 bytes를 바디로 해석합니다.

13.3 바디 수신 단계: Filter(byte[])

public override TRequestInfo? Filter(
    byte[] readBuffer,
    int offset,
    int length,
    bool toBeCopied,
    out int rest)
{
    if (!m_FoundHeader)
        return base.Filter(readBuffer, offset, length, toBeCopied, out rest);

    if (m_BodyBuffer == null || m_BodyBuffer.Count == 0)
    {
        if (length < m_BodyLength)
        {
            if (m_BodyBuffer == null)
                m_BodyBuffer = new ArraySegmentList();

            m_BodyBuffer.AddSegment(readBuffer, offset, length, toBeCopied);
            rest = 0;
            return NullRequestInfo;
        }
        else if (length == m_BodyLength)
        {
            rest = 0;
            m_FoundHeader = false;
            return ResolveRequestInfo(m_Header, readBuffer, offset, length);
        }
        else
        {
            rest = length - m_BodyLength;
            m_FoundHeader = false;
            return ResolveRequestInfo(m_Header, readBuffer, offset, m_BodyLength);
        }
    }

    int required = m_BodyLength - m_BodyBuffer.Count;

    if (length < required)
    {
        m_BodyBuffer.AddSegment(readBuffer, offset, length, toBeCopied);
        rest = 0;
        return NullRequestInfo;
    }
    else if (length == required)
    {
        m_BodyBuffer.AddSegment(readBuffer, offset, length, toBeCopied);
        rest = 0;
        m_FoundHeader = false;
        var requestInfo = ResolveRequestInfo(m_Header, m_BodyBuffer.ToArrayData());
        m_BodyBuffer.ClearSegements();
        return requestInfo;
    }
    else
    {
        m_BodyBuffer.AddSegment(readBuffer, offset, required, toBeCopied);
        rest = length - required;
        m_FoundHeader = false;
        var requestInfo =
            ResolveRequestInfo(m_Header, m_BodyBuffer.ToArrayData(0, m_BodyLength));
        m_BodyBuffer.ClearSegements();
        return requestInfo;
    }
}

13.4 구현자가 반드시 제공해야 하는 두 메서드

protected abstract int GetBodyLengthFromHeader(
    byte[] header,
    int offset,
    int length);

protected abstract TRequestInfo? ResolveRequestInfo(
    ArraySegment<byte> header,
    byte[]? bodyBuffer,
    int offset,
    int length);

첫 번째 메서드는 헤더를 읽어 바디 길이를 반환합니다. 두 번째 메서드는 헤더와 바디를 도메인 requestInfo로 변환합니다.

14. EchoServer 예제로 보는 실제 필터

Tutorials/EchoServer/ReceiveFilter.cs는 헤더 5바이트, 바디 가변 길이 구조를 사용합니다. 헤더는 TotalSize(2), PacketID(2), Value1(1)로 구성됩니다.

14.1 RequestInfo 모델

public class EFBinaryRequestInfo : BinaryRequestInfo
{
    public Int16 TotalSize { get; private set; }
    public Int16 PacketID { get; private set; }
    public SByte Value1 { get; private set; }

    public const int HeaderSize = 5;

    public EFBinaryRequestInfo(
        Int16 totalSize,
        Int16 packetID,
        SByte value1,
        byte[] body)
        : base(null, body)
    {
        this.TotalSize = totalSize;
        this.PacketID = packetID;
        this.Value1 = value1;
    }
}

14.2 ReceiveFilter 구현

public class ReceiveFilter : FixedHeaderReceiveFilter<EFBinaryRequestInfo>
{
    public ReceiveFilter() : base(EFBinaryRequestInfo.HeaderSize)
    {
    }

    protected override int GetBodyLengthFromHeader(
        byte[] header,
        int offset,
        int length)
    {
        if (!BitConverter.IsLittleEndian)
            Array.Reverse(header, offset, 2);

        var packetTotalSize = BitConverter.ToInt16(header, offset);
        return packetTotalSize - EFBinaryRequestInfo.HeaderSize;
    }

    protected override EFBinaryRequestInfo ResolveRequestInfo(
        ArraySegment<byte> header,
        byte[] buffer,
        int offset,
        int length)
    {
        if (!BitConverter.IsLittleEndian)
            Array.Reverse(header.Array, 0, EFBinaryRequestInfo.HeaderSize);

        return new EFBinaryRequestInfo(
            BitConverter.ToInt16(header.Array, 0),
            BitConverter.ToInt16(header.Array, 2),
            (SByte)header.Array[4],
            buffer.CloneRange(offset, length));
    }
}

14.3 서버에서 필터를 연결하는 방식

class MainServer : AppServer<NetworkSession, EFBinaryRequestInfo>
{

        : base(new DefaultReceiveFilterFactory<ReceiveFilter, EFBinaryRequestInfo>())

15. 패킷 시나리오별 흐름

실제 네트워크에서는 패킷 경계와 receive 경계가 일치하지 않습니다. 아래 단계별 버튼으로 세 가지 대표 상황을 비교할 수 있습니다.

요청 하나가 딱 맞게 도착

필터가 바로 requestInfo를 반환하고 rest=0입니다. AppSession 루프는 handler를 호출한 뒤 종료합니다.

Filter(...) -> requestInfo != null, rest = 0
AppServer.ExecuteCommand(session, requestInfo)
return offsetDelta

요청 하나가 쪼개져 도착

첫 receive에서는 requestInfo가 null이고 OffsetDelta가 누적 길이를 가리킵니다. 다음 receive bytes는 carry buffer의 그 위치에 붙습니다.

1st receive:
  Filter(...) -> null
  OffsetDelta = 4

2nd receive:
  writeOffset = 4
  sequence.CopyTo(_filterBuffer[4..])
  Filter(...) -> requestInfo

여러 요청이 한 번에 도착

첫 요청을 만들고 rest>0이면 AppSession 루프가 offset/length를 남은 bytes로 갱신해 다시 필터를 호출합니다.

Filter(...) -> requestInfo1, rest = 8
ExecuteCommand(requestInfo1)
offset = offset + length - rest
length = rest
Filter(...) -> requestInfo2, rest = 0
ExecuteCommand(requestInfo2)

16. 오류, 종료, backpressure

수신 경로에서 오류는 크게 socket 수신 실패, 프로토콜 파싱 실패, 요청 길이 초과, Pipe 종료로 나뉩니다.

Socket 수신 실패

ProcessCompleted(e)가 false이면 _pipeWriter.Complete() 후 OnReceiveTerminated()를 호출합니다.

프로토콜 예외

ProcessPipeAsync()에서 AppSession.ProcessRequest() 예외를 잡으면 CloseReason.ProtocolError로 닫습니다.

MaxRequestLength 초과

FilterRequest()가 현재 요청 길이를 계산해 설정값보다 크면 프로토콜 오류로 닫습니다.

Flush backpressure

FlushAsync()가 즉시 완료되지 않으면 continuation에서 다음 receive를 시작합니다. 소비자가 따라올 때까지 receive 재개를 늦춥니다.

수신 상태 플래그

protected bool OnReceiveStarted()
{
    if (AddStateFlag(SocketState.InReceiving, true))
        return true;

    ValidateClosed(CloseReason.Unknown, false);
    return false;
}

protected void OnReceiveEnded()
{
    RemoveStateFlag(SocketState.InReceiving);
}

protected void OnReceiveTerminated(CloseReason closeReason)
{
    OnReceiveEnded();
    ValidateClosed(closeReason, true);
}
receive 중 close가 들어오거나, close 중 새 receive가 시작되는 상황을 막기 위해 상태 플래그가 필요합니다. 수신 파이프라인을 수정할 때 이 플래그 흐름을 건드리면 close race가 생길 수 있습니다.

17. 코드를 읽을 때 확인할 체크리스트

수신 파이프라인 체크

  • StartReceive()가 PipeWriter memory를 SAEA buffer로 설정하는지 확인합니다.
  • ProcessReceive()가 파싱하지 않고 Advance()/FlushAsync()만 하는지 확인합니다.
  • FlushAsync() 지연 시 다음 receive가 continuation에서 재개되는지 확인합니다.
  • ProcessPipeAsync()가 예외를 ProtocolError로 처리하는지 확인합니다.
  • CompleteReceivePipe()가 pipe loop 종료 후 호출되는지 확인합니다.

ReceiveFilter 체크

  • Filter()가 requestInfo/null/rest를 정확히 반환하는지 확인합니다.
  • 부분 패킷일 때 LeftBufferSize와 OffsetDelta가 올바른지 확인합니다.
  • 한 receive에 여러 요청이 들어올 때 rest가 정확한지 확인합니다.
  • 헤더 길이와 바디 길이 계산이 MaxRequestLength와 충돌하지 않는지 확인합니다.
  • 엔디언 처리와 CloneRange() 사용 위치가 의도와 맞는지 확인합니다.
수신 경로에서 가장 흔한 버그는 “TCP receive 경계와 패킷 경계를 동일하게 가정”하는 것입니다. 이 라이브러리는 그 문제를 Pipe, carry buffer, receive filter, rest loop로 나누어 처리합니다.
